## 1. 결정 사항(사용자 2026-11-12)

| # | 결정 |
|---|---|
| 1 | 케이토목을 지우지 않고 여러 업체 상품을 **함께** 보인다(오픈마켓). 업체 활성/비활성으로 고객 노출만 바꾸고 DB 는 유지 |
| 2 | 행 = **업체 × 제품**(가격·치수·배송이 업체마다 다름). '한길콘크리트 외 1' 처럼 묶지 않음 |
| 3 | **표준 분류 = 기존 `categories`(재질 기준)** — 상단 재질 메뉴 그대로. 업체 분류는 **매핑 표**로 연결(다대일, 상품 단위 규칙) |
| 4 | 업체 원본 표는 따로, 고객은 **합친 표(`products`)** 를 본다. 합칠 때 열쇠는 상품명이 아니라 **(출처, 출처ID)** |
| 5 | 상세가 같아도 데이터는 업체별 행. 화면에서만 나란히/묶어 보이기(나중) |
| 6 | 기존 `vendors` 4곳은 **샘플** |
| 7 | 원본 → 합친 표 반영에 **가격 칸 포함 허용**(새 행에만 — 기존 케이토목 가격·분류 변경 없음) |
| 8 | 매핑 대조표·치수 칸 맞춤 **추천대로 확정** |

## 2. 구조

```
[업체 원본]   products(케이토목 1,319행 — 그대로, 업체만 표시)   syc_products(상용콘크리트)   (이후 업체: 공통 원본 표)
                    │                                              │ 자동 정리(app/syc_normalize*.php)
                    │                                              │ 분류 매핑 vendor_category_map → 표준 분류
                    │                                              │ 칸 맞춤  vendor_axis_map → 표준 칸 / 상세(dim_extra)
                    ▼                                              ▼  (출처, 출처ID) 로 덮어쓰기 — 관리자 '고객용 반영'
[고객용]      products  = 업체 × 제품 (vendor_id) ── categories(표준 분류, 재질 메뉴) ── category_spec_axes(표준 규격 칸: 목록 in_list=1 / 상세 0)
              vendors   = 판매 업체(케이토목·상용콘크리트) — 비활성 업체 상품은 고객 화면에서 숨김
```

- **목록 = 표준 규격 칸(업체 공통)**, 업체 고유 칸 = 상세 화면만 → 같은 품목에서 업체가 달라도 한 표로 비교.
- 고객 화면·장바구니·견적·주문·AI 상담은 지금처럼 `products` 만 본다(코드 변경 최소). **견적·주문 기록 0건**(2026-11-12) — 구조를 바꾸기 좋은 시점.

## 3. 표 변경(모두 추가형 — 기존 칸·행·가격 변경 없음) — `multi-vendor-sql/01_ddl.sql`

| 표 | 변경 | 이유 |
|---|---|---|
| `vendors` | `code`(업체 코드, UNIQUE) 추가 | 원본 출처·매핑이 업체를 가리키는 이름(ktomok·syccrt) |
| `products` | `vendor_id`(+인덱스), `dim_t_mid`·`dim_x1`·`dim_x2`(목록 칸), `dim_extra` JSON(상세 전용 치수), `image_thumb_url` | 업체별 행, 업체 칸 채택(2련암거 중간벽·파형강관 파형 피치/깊이), 상세 치수 44종을 칸 40개 대신 JSON 1칸, 목록용 작은 이미지. `dim_t2` 는 이미 있음 |
| `category_spec_axes` | `axis_key` ENUM → VARCHAR(20)(넓힘), `in_list` 추가(기본 1) | 업체 고유 칸 이름표, 목록/상세 구분. 기존 520행 그대로(in_list=1) |
| `vendor_category_map`(새) | 업체·업체 분류·조건(all/code/option/name)·표준 분류·신뢰도 | 다대일 매핑 + 상품 단위 규칙(측구수로관 A·B·AN·Z형 등) |
| `vendor_axis_map`(새) | 매핑 1줄마다 업체 칸 → 표준 칸(column) / 상세(extra) | 같은 뜻 다른 이름 41곳(높이 H → 깊이 등) |

- 가격 표(`products`·`categories`)에는 **FOREIGN KEY 를 넣지 않음**(원격 관리 API 가 가격 표 구조 변경을 ADD COLUMN·인덱스만 허용) — 인덱스 + 코드에서 존재 확인.

## 5. 반영(동기화) — 다음 개발 단계

관리자 제품관리에 **'고객용 반영'**(업체별): 원본 행 → 자동 정리 → 분류 매핑(조건 순서: code·option·name → all) → 칸 맞춤 → `products` 에 (출처, 출처ID) 로 덮어쓰기(`vendor_id`, 가격 칸 포함 — 결정 7).
- **미리보기 먼저**(일괄 등록 자동 정리와 같은 방식): 새로 넣음·고침·숨김 수, 매핑 안 된 상품(경고), 칸 충돌.
- 원본에서 사라진 상품 → `products.is_active = 0`(지우지 않음). 원본 활성 상태 = 고객용 활성 상태.
- 가격: 새 행의 `category_id` = 표준 분류 → 마진율 상속(지금 245개 모두 20/10 — 계산 같음). **기존 케이토목 행의 가격·분류는 건드리지 않음.** 원격 관리 API 로는 못 함(가격 칸) — 관리자 화면 기능으로.

## 6. 고객 화면 변경 — 다음 개발 단계

- 상품 조회에 `vendor_id IS NULL OR 업체 활성` 조건, 업체 칸 = `vendors.name`(지금의 product_vendors 샘플 표시 대신).
- 목록 칸 = 이름표 `in_list=1`, 상세 = 목록 칸 + `in_list=0` 칸(`dim_extra`) — 상용콘크리트 상세 화면(주요/세부 치수) 방식을 고객 상세에 이식.
- 목록 이미지 = `image_thumb_url` 있으면 그것.
- 관리자 '사이트 보기(케이토목/상용콘크리트)' 미리보기는 반영 뒤 정리(업체 활성 토글로 대체).
- 업체관리: 디자인 '업체관리(After)' 업체 목록 — 케이토목·상용콘크리트, 활성/비활성.

## 9. 남은 결정

- `products` 의 외부 출처 `dacity` 10행(1련암거)·출처 없음 12행의 업체: 지금 초안은 업체 미지정(NULL, 계속 보임).
- 인조화강블록 투수/불투수(상용 2품목): 한 상품에 둘 다 — 상품을 투수·불투수로 나눌지(업체 데이터 확인).
- 신뢰도 '하' 10줄(흄관 A/B형, 사각수로관 A→AN, 보강토 무늬 등) — 실제 데이터를 받으면 다시 확인.
- 같은 규격 업체 행 묶어 보이기(5번 결정) — 업체 3곳 이상일 때.
