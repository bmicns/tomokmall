작성 2026-11-10 · 상태: **표만 만들어 둠(코드에서 아직 사용 안 함)**

| 파일 | 내용 |
|---|---|
| `database/20261110_syc_categories.sql` | 전용 카테고리 표 + 대분류 10 · 품목 81 (91행), 마진율은 기존 `categories` 에서 복사 |

## 1. products 와 다른 점

| 항목 | products | syc_products |
|---|---|---|
| 카테고리 | `categories.id` | `syc_categories.id` |
| 이미지 | `image_url`(외부 주소 1개, 실제로는 40×40 썸네일) | 크기 2가지: `image_file`(대표·상세용 큰 이미지) + `image_thumb_file`(썸네일·목록용 작은 이미지) — 이미지 ZIP 에서 꺼내 서버에 저장한 파일 경로 |
| 모델코드 | `spec_code` = 규격 괄호 속 코드 | `spec_code` = 카탈로그 **호칭** |
| 치수 칸 | 케이토목 규격 기준 | 상용콘크리트 카탈로그 머리글 기준 + **도면 세부 치수 칸**(아래 2장) |
| `spec_option` | VARCHAR(80) | VARCHAR(160) — 치수·모델코드 외 나머지 |
| `main_category` | 있음(코드 미사용) | 없음 |
| `is_active` 기본값 | 1 | 0(일괄 등록은 비활성 저장) |

## 2. 카탈로그 머리글 → 칸

- 숫자 치수는 mm(카탈로그가 m 표기면 ×1000), 중량은 kg(t 표기면 ×1000) → `weight_kg`.
- **대표 치수**는 뜻 이름 칸(`dim_w`·`dim_h`·`dim_l`·`dim_t` …), **도면 세부 치수**는 카탈로그 기호 그대로 번호 칸
  (`dim_w1`·`dim_w2`, `dim_h1`~`h4`, `dim_t1`·`dim_t2`·`dim_t3`·`dim_t4`, `dim_l1`~`l6`, `dim_d1`~`d5`, `dim_r1`·`r2`, `dim_c`, `dim_x1`~`x4`).
  같은 번호 칸도 품목마다 뜻이 다르므로 이 표가 기준이다.
- 치수·모델코드가 아닌 값(그레이팅 규격, 비고, 재질, 설치방식, 철근 지름·개수, 균열·파괴 하중 등)은 `spec_option`.
- 벤치플륨 Ⅱ·Ⅲ 의 소켓부 치수 aS·cS·dS·eS·hS·lS·l'(예: '261이상' — 최소값 표기)와 허용차(±3 등)·배근은 `description` 에 원문 그대로.

- 암거·개거 두께: T1 = 상판, T2 = 하판, T3 = 측벽(사용자 제공 도면). 2련 T4 는 중간벽으로 둠(2련 도면 확인 시 수정).

## 5. 이미지 구조 확인(2026-11-11, 운영 읽기 전용 조회)

- 기존 `products` 는 이미지 칸이 **1개(`image_url`)** 다. 1,341개 중 1,329개에 값, 모두 외부 주소(ktomok.com 1,319 · dacity.kr 10).
- 그 1,319개는 원본이 아니라 **40×40 썸네일**(`thumb-…_40x40.jpg`)이다. 목록(`products.php`)·관련 상품·상세 큰 이미지(`product.php` `#main-prod-img`)가
  모두 이 한 장을 쓰므로 상세 화면은 40px 이미지를 늘려 보여 준다.
- 상세 화면의 여러 장 갤러리는 상품이 아니라 **카테고리 단위** 표(`category_gallery`: category_id·image_url·caption·sort_order, 26개 카테고리 78장)다.
- 결론: 화면에는 크기 2가지(목록용 작은 이미지, 상세용 큰 이미지)가 필요하다. 다만 올리는 사람이 2장을 따로 만들 필요는 없다 —
  대표(원본) 1장을 받고 썸네일은 서버(PHP GD, 설치됨)가 만들면 된다. 테스트 ZIP 은 두 방식 모두 시험할 수 있게 대표+썸네일을 같이 넣었다.
  → 사용자 결정(2026-11-11): `syc_products` 에 두 크기를 따로 둔다 — `image_file`(대표·상세용) + `image_thumb_file`(썸네일·목록용).
  엑셀은 두 칸에 ZIP 안 파일명(`{출처ID}.jpg`·`{출처ID}_thumb.jpg`).
  → 썸네일(…_thumb)이 엑셀·ZIP 에 없으면 비워 두고(NULL) 화면은 기존 '이미지 없음' 표시를 그대로 쓴다(사용자 결정 2026-11-11). 기존 표시: 관리자 목록 `.prod-no-img`, 관리자 상세 `.img-empty`(이미지 없음), 상품 상세 `.pd-img-empty-msg`(이미지 준비 중).

## 9. 업체 엑셀 자동 정리(2026-11-11)

업체가 다음 자료를 예전 표기(품명 '측구수로관 앵글부착 B형', 모델 코드 '300*400B', 옵션 '그레이팅 395*995*50', 나누기·합치기 전 분류코드)로 보내도
**등록 전에** 사이트 표기 원칙(품명 = 제품명만, 모델 코드 = 형식만, 옵션 = 글자만, 치수 = 칸, 분류 = 지금 카테고리)으로 고친다. 반복 수작업을 없애는 것이 목적.

### 9-1. 구조

| 층 | 파일 | 책임 |
|---|---|---|
| 규칙(데이터) | `app/syc_normalize_rules.php` | 분류 합치기·나누기 묶음(치수 칸 구성), 옵션으로 옮길 글자, 옵션 속 치수 패턴 → 칸. **카테고리를 다시 나누거나 합치면 이 파일만 고친다** |
| 엔진(순수 함수) | `app/syc_normalize.php` | 규칙을 행에 적용, 바꾼 곳마다 [행·칸·전·후·규칙] 기록. DB·파일·세션을 모름 → 테스트로 결과 고정 |

### 9-2. 단계(순서 고정)

1. 분류 합치기(숨긴 카테고리 → 모은 카테고리) 2. 분류 나누기(값이 있는 목록 치수 = 묶음의 어느 카테고리) 3. 옵션 속 치수 → 칸(칸이 비어 있을 때만 — 업체 값 우선, 다르면 경고)
4. 모델 코드(카테고리 단위 — 모든 코드가 '크기[+형식]' 이고 크기가 치수 칸에 있을 때만: B형·W2·옵션 글자·비움) 5. 품명(옵션 글자 → 옵션 앞, 형식과 같은 낱말 → 뺌)

### 9-3. 안전장치

- 가격·출처·이미지·규격 원문·중량·단위·업체 칸은 읽지도 바꾸지도 않음(테스트가 704행 대조).

- 멱등: 정리된 엑셀을 다시 넣으면 바뀌는 곳 0(테스트).
- 창에서 끄면 엑셀 그대로 등록. 등록 결과에 정리한 상품 수 표시.

## 12. 목록 표 규격 두 칸(2026-11-13 사용자 결정, S17)

- 고객 목록(`public/products.php`)의 규격을 칸별 축(모델 코드·폭 W·높이 H…·옵션, 두 줄 머리글) 대신 **'규격'(치수)·'규격외정보'** 두 칸으로 통일 — 케이토목·상용콘크리트 공통, 참고 화면은 예전 디자인 시안(사진·품명·단위·규격·규격외정보).
- 규격 = 규격 원문(`products.spec` 의 '규격:' 조각). 끝 괄호 안이 치수 아닌 글자('(A형)'·'(앙카식)')면 규격외정보로 옮기고, 치수 목록('(320*320*2000*60T)')이면 그대로.
- 규격외정보 = 모델 코드(`spec_code`) + 옮긴 괄호 글자 + 옵션(`spec_option`, 표시 형식 — 밑줄 → '/'), 같은 글자는 한 번, ' / ' 로 이음. 모델 코드·옵션은 축 값이 지금 규격 기준일 때만(`spec_axes_row_fresh`). 함수 `product_list_spec_split()`(`app/spec_axes.php`).
- 그대로인 것: 상품 상세 화면의 주요/세부 치수, DB 칸·이름표. 필터로 고른 값의 표 칸 강조(is-hit)는 목록에 칸이 없어 없어짐.
- **왼쪽 필터(같은 날 추가 결정)**: 축별 그룹(모델 코드·폭 W…) 대신 **'규격(치수)' 한 그룹** — 값 = 목록 '규격' 칸과 같은 치수(`product_facets`·`product_filter_sql` 이 `product_list_spec_split` 기준, 원문 끝에 '(A형)' 이 붙은 상품도 같은 치수로 찾음). 축별 그룹 함수(`product_filter_axis_groups`)는 남겨 두고 쓰지 않음.
- 업체별 행: 업체가 다르면 항상 다른 행(묶지 않음). 지금 고객 목록은 상용콘크리트만(고객 화면 고정).
- 대체한 결정: S10 '목록 표 모델 코드 칸 유지', 규격 구조화(`docs/02-design/spec-axes.md`)의 목록 축 칸 표시.

## 14. 임시 가격(2026-11-16 사용자 요청, S19)

- 왜: 상용콘크리트 원본에 가격이 없어(0원) 고객 화면이 모두 '견적문의'(0원 표시 결정 O4). 사용자가 일반·개인·기업 가격이 보이도록 임시 가격을 요청했고, 같은 날 `CLAUDE.md` P0-4-1 에 '일괄 등록 엑셀의 가격 작성' 예외를 두었다(실제 저장은 사용자 관리자 화면).
- 규칙: 매입가 = 중량(kg) × 150원, 천 원 단위 반올림, 최소 1,000원, 중량 없는 145개는 10,000원. `price_b2c`(비회원·일반가) = 매입가 × 1.3, `price_b2b` = 매입가 × 1.1(100원 반올림). 개인·기업 회원가는 화면이 매입가 × (1 + 마진율 20%/10%)로 계산(S6).
- 결과(704행): 매입가 최소 1,000원·가운데 78,000원·최대 2,564,000원.
- 반영: 관리자 › 제품관리 › 상용콘크리트 일괄 등록(같은 출처ID 덮어쓰기, 가격 칸 = 엑셀 값 — S5) → '사이트에 반영'(원본 → 고객용 상품 표 복사).
- 되돌리기·교체: 실제 가격 엑셀을 같은 방법으로 다시 올리면 덮어씀. 0원으로 되돌리려면 `syc-products-upload.xlsx`(가격 0) 를 올리고 반영.

## 16. 업체 활성/비활성(2026-11-17 사용자 결정, S23)

- 기준 시안: 디자인 아트보드 '관리자' 페이지 '업체관리(After)'. 정리 문서: '업체 활성화·비활성화 기능 개발 정리'(2026-11-17).
- 직원 이상이 직원 화면 '품목별 업체정보' → 업체 목록에서 [비활성]/[재활성](`public/api/staff/vendors.php` `set_vendor_active`). 업체 목록에 상태 탭(활성·비활성·전체).
- **비활성**: 업체(`vendors.is_active = 0`) + 그 업체 상품 전부 비활성 — 원본 `syc_products`(출처 `vendor-<id>`)와 고객용 반영본 `products`(같은 출처) 둘 다(`app/vendors.php` `vendor_deactivate_products`). 고객 화면 업체명에서도 빠짐(기존 `vendor_names_subquery`). 품목 연결(`product_vendors`)·공급단가는 그대로.
- **재활성**: 업체만 활성. 상품은 비활성 그대로 — 관리자가 제품관리에서 직접 활성으로.
- 업체가 비활성인 동안 그 업체 상품은 활성으로 바꿀 수 없다(제품관리 선택·검색 결과 전체·수정 창 — `app/product_sources.php` `product_assert_no_inactive_vendor`). 제품관리 드롭다운에는 '업체명 (비활성)'으로 남아 원본 수정·일괄 등록은 된다(새 상품은 원래대로 비활성).
- 품목의 [업체 관리] 창: 비활성 업체 회색·'비활성' 표시, 주거래가 비활성이면 경고, [주거래로 지정](공급단가 그대로, 비활성 업체는 지정 불가). 품목별 보기 업체수 = 활성 업체만(비활성 수 따로).
- 케이토목·상용콘크리트는 업체 목록(`vendors`) 행이 아니라 대상이 아니다.

## 17. 업체 연결 = 업체 상품(2026-11-17 사용자 결정, S24)

- 정리 문서: '업체 활성화·비활성화 기능 개발 정리' 마지막 절 '다음 단계: 업체 연결 = 업체 상품'. 결정: 가안(고객용 상품 표에 바로, DB 구조 변경 없음) + **비활성으로 시작**, 비회원가 = 원래 상품 정가 복사.
- 추가(`public/api/staff/vendors.php` `add_product_vendor`, `app/vendors.php` `vendor_link_upsert`): 연결(`product_vendors`) 저장과 같은 트랜잭션에서 `products` 에 업체 상품 줄을 만든다.
  - 출처 `vendor-<업체 id>`, 출처ID `link-<원래 상품 id>`, 브랜드 = 업체명, 매입가(`cost_price`) = 공급단가, 그 밖의 칸(분류·이름·규격·치수·이미지·`price_b2c`·`price_b2b` 등)은 원래 상품 복사, `is_active = 0`.
  - 이미 줄이 있으면(삭제 후 다시 추가 포함) 매입가·브랜드만 고치고 활성 상태는 그대로.
  - 막는 경우: 업체 상품 줄에 다시 업체 추가, 비활성 업체 새로 추가.
- 고객 화면: 업체 상품 줄은 별도 행(S17). 원래 상품 줄의 업체명(`vendor_names_subquery`)에서는 자기 줄이 있는 업체를 뺀다.
- 제품관리 '모든 업체': 업체 상품 줄은 저장 위치 `link`(원본 없음) → 수정 창·활성/비활성이 `products` 를 바로 고친다. 수정 창 매입가를 바꾸면 그 업체 공급단가도 같이 바뀐다. 업체별 보기(원본 표)에는 나오지 않는다.
- 삭제(공급 제외): 경고 창 → 연결 삭제 + 상품 줄 비활성(행은 남김 — 견적·주문 기록이 가리킴). 연결이 없는 상품 줄은 활성으로 바꿀 수 없다(다시 추가 후).
- 업체 비활성(S23)은 이 줄도 함께 끈다(출처가 같음). 공통 분류 반영(`syc_publish_std_apply`)의 '원본 없음 → 숨김'은 `link-` 줄을 건드리지 않는다.
- 지금은 없는 상품(비활성) 표시: 견적 요청 화면(`public/estimate.php`) 회색 줄 + '지금은 없는 상품입니다' + X(금액·접수에는 원래대로 안 들어감), 상품 상세(`public/product.php`)는 상세 대신 안내 화면, 납품 이력 요약 '(지금은 없는 상품)', 직원 견적 상세 회색 표시.
- 이번 범위 밖: 이미 있던 연결(이 기능 전 `product_vendors`)은 업체 상품 줄이 없다 — 필요하면 그 업체를 [공급 제외] 후 다시 추가. 원래 상품의 이름·규격·이미지를 나중에 고쳐도 업체 상품 줄은 따라 바뀌지 않는다(제품관리에서 직접).

## 22. 업체 엑셀 자동 정리 — 칸 맞추기·분류 추천(2026-11-23 사용자 결정, S31)

- 왜: S30 은 관리자가 엑셀 분류코드 칸에 고객 화면 분류코드를 직접 적어야 했다. 대안 비교(관리자 화면 자동 처리 / 처리 절차 문서 + Claude 가 매번 엑셀 정리 / 둘 다) 후 사용자 선택 = **관리자 화면 자동 처리**(Claude 의 기억에 기대지 않고 매번 같은 결과).
- 흐름: 업체 엑셀을 그대로 올림 → **칸 맞추기**·**분류 정하기** 표 확인(노란 줄·빨간 줄만) → 기존 자동 정리·검사 → 등록. 미리보기와 등록은 같은 함수·같은 옵션(`syc_bulk_read_excel` 의 `$auto`, 세션에 둔 칸 맞추기·고른 분류).
- 칸 맞추기(`syc_bulk_columns_auto`): 순서 = 관리자가 고른 칸(머리글 글자 → 칸, '' = 안 씀) → `[칸 이름]`·칸 이름(양식 칸) → 한글 별칭(`SYC_BULK_HEADER_ALIASES`, 짐작). 짐작한 칸은 앞 20행 값 중 절반 넘게 칸 규칙에 안 맞으면 쓰지 않음(예: 동아산업 '사진' 칸의 '사진 보기' 글자). 같은 칸이 둘이면 앞의 것만. **가격 칸(price_b2c·price_b2b·cost_price)은 별칭이 없다** — 업체 '단가'가 매입가인지 판매가인지 모르므로 관리자가 고른다(가격 저장 경로·값은 기존 일괄 등록 그대로, P0-4). 필수 칸은 상품명뿐(분류는 추천).
- 분류 추천(`syc_bulk_suggest_category`): 분류코드가 빈 행만. 업체 분류명(카테고리)·중분류·상품명 ↔ 고객 화면 분류(S30 목록) 끝 단계 이름. 글자 정리(띄어쓰기·기호 무시, 블럭→블록, 휀스→펜스) 후 이름 같음 = **확실**, 포함·비슷함(두 글자 묶음 유사도, 중분류가 같으면 가산) = **확인 필요**, 점수 낮음 = **못 정함**. 묶음(업체 중분류 › 분류명, 없으면 상품명)마다 한 번 계산하고 관리자가 고른 값(분류 slug 또는 '-' = 등록 안 함)이 우선. 숨긴 분류는 목록에 없어 '확인 필요'로 다른 분류가 추천될 수 있음 → 노란 줄 확인.
- 기억: 칸 맞추기·고른 분류는 업체별로 **이 브라우저**(localStorage `tomok.bulk.map/cats.<업체 코드>`)에 둔다 — DB 구조 변경 없음. 다른 PC 에서는 다시 고름. '이 업체용 기억 지우기' 버튼.
- 시험(11-23): 동아산업 원본 크롤링 엑셀에서 분류코드 칸을 지우고 운영 공통 분류 217개로 추천 — 묶음 212개 중 확실 174(그중 172개가 S29 번호 연결과 같음, 2개는 취급 중단 암거의 옛/새 slug 차이), 확인 필요 36(대부분 숨긴 분류·몰드), 못 정함 2(아스콘·환경생태블록). 칸: 품명·규격·단위·중량·품번·설명·출처주소 = 양식 칸, 대분류·중분류·규격외정보 = 짐작, 사진 = 값이 주소가 아니라 안 씀. 운영 복제 개발 DB + 로컬 서버(관리자 세션)로 화면 업로드·칸 고치기·'등록 안 함'·등록까지 확인(데스크톱 1280·모바일 390, 가로 넘침 없음).
- 상차수량 칸(사용자 요청 2026-11-24): `syc_products.load_qty` DECIMAL(10,2) NULL 추가(`database/20261124_syc_products_load_qty_phpmyadmin.sql`, 사용자 phpMyAdmin — DB 먼저, 코드 배포 나중). 일괄 등록 엑셀 칸 `load_qty`(별칭 상차수량·상차·적재수량)로 저장. 고객 화면·운반비 계산에는 쓰지 않음(D11 그대로), 반영본(`products`)에는 복사하지 않음. 상차 기준(예 '본/25톤')은 칸 없음.
- 숨겨진 분류(사용자 결정 2026-11-24, S32): 번호 연결로 동아산업 325개가 숨긴 품명 줄에 들어감(같은 이름 중분류·품명 구조 238 + SUS그레이팅 2 + 몰드 85), 상용콘크리트도 110개(파형강관 102·콘크리트경계석 6·잔디블록 2)가 같은 이유로 안 보였음. 같은 이름 구조 5곳은 보이는 중분류로 연결(마진율 20/10 같음 확인). 반영은 다음 공통 분류 반영 때(일괄 등록·활성 변경). 카테고리 관리 화면 비활성 글자 취소선 제거(회색 유지).
