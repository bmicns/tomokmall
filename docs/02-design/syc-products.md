작성 2026-11-10 · 상태: **표만 만들어 둠(코드에서 아직 사용 안 함)**

| 파일 | 내용 |
|---|---|
| `database/20261110_syc_categories.sql` | 전용 카테고리 표 + 대분류 10 · 품목 81 (91행), 마진율은 기존 `categories` 에서 복사 |

## 1. products 와 다른 점

| 항목 | products | syc_products |
|---|---|---|
| 카테고리 | `categories.id` | `syc_categories.id` |
| 이미지 | `image_url`(외부 주소 1개, 실제로는 40×40 썸네일) | 크기 2가지: `image_file`(대표·상세용 큰 이미지) + `image_thumb_file`(썸네일·목록용 작은 이미지) — 이미지 ZIP 에서 꺼내 서버에 저장한 파일 경로 |
| 모델코드 | `spec_code` = 규격 괄호 속 코드 | `spec_code` = 카탈로그 **호칭** |
| 치수 칸 | 케이토목 규격 기준 | 상용콘크리트 카탈로그 머리글 기준 + **도면 세부 치수 칸**(아래 2장) |
| `spec_option` | VARCHAR(80) | VARCHAR(160) — 치수·모델코드 외 나머지 |
| `main_category` | 있음(코드 미사용) | 없음 |
| `is_active` 기본값 | 1 | 0(일괄 등록은 비활성 저장) |

## 2. 카탈로그 머리글 → 칸

- 숫자 치수는 mm(카탈로그가 m 표기면 ×1000), 중량은 kg(t 표기면 ×1000) → `weight_kg`.
- **대표 치수**는 뜻 이름 칸(`dim_w`·`dim_h`·`dim_l`·`dim_t` …), **도면 세부 치수**는 카탈로그 기호 그대로 번호 칸
  (`dim_w1`·`dim_w2`, `dim_h1`~`h4`, `dim_t1`·`dim_t2`·`dim_t3`·`dim_t4`, `dim_l1`~`l6`, `dim_d1`~`d5`, `dim_r1`·`r2`, `dim_c`, `dim_x1`~`x4`).
  같은 번호 칸도 품목마다 뜻이 다르므로 이 표가 기준이다.
- 치수·모델코드가 아닌 값(그레이팅 규격, 비고, 재질, 설치방식, 철근 지름·개수, 균열·파괴 하중 등)은 `spec_option`.
- 벤치플륨 Ⅱ·Ⅲ 의 소켓부 치수 aS·cS·dS·eS·hS·lS·l'(예: '261이상' — 최소값 표기)와 허용차(±3 등)·배근은 `description` 에 원문 그대로.

## 3. 확인된 사항(2026-11-10)

- 암거·개거 두께: T1 = 상판, T2 = 하판, T3 = 측벽(사용자 제공 도면). 2련 T4 는 중간벽으로 둠(2련 도면 확인 시 수정).

- 마진율 복사 기준(대분류 → 기존 카테고리)은 `20261110_syc_categories.sql` [5] 주석 참고. 2026-11-10 운영 값은 모두 개인 20 / 기업 10.

## 5. 이미지 구조 확인(2026-11-11, 운영 읽기 전용 조회)

- 기존 `products` 는 이미지 칸이 **1개(`image_url`)** 다. 1,341개 중 1,329개에 값, 모두 외부 주소(ktomok.com 1,319 · dacity.kr 10).
- 그 1,319개는 원본이 아니라 **40×40 썸네일**(`thumb-…_40x40.jpg`)이다. 목록(`products.php`)·관련 상품·상세 큰 이미지(`product.php` `#main-prod-img`)가
  모두 이 한 장을 쓰므로 상세 화면은 40px 이미지를 늘려 보여 준다.
- 상세 화면의 여러 장 갤러리는 상품이 아니라 **카테고리 단위** 표(`category_gallery`: category_id·image_url·caption·sort_order, 26개 카테고리 78장)다.
- 결론: 화면에는 크기 2가지(목록용 작은 이미지, 상세용 큰 이미지)가 필요하다. 다만 올리는 사람이 2장을 따로 만들 필요는 없다 —
  대표(원본) 1장을 받고 썸네일은 서버(PHP GD, 설치됨)가 만들면 된다. 테스트 ZIP 은 두 방식 모두 시험할 수 있게 대표+썸네일을 같이 넣었다.
  → 사용자 결정(2026-11-11): `syc_products` 에 두 크기를 따로 둔다 — `image_file`(대표·상세용) + `image_thumb_file`(썸네일·목록용).
  엑셀은 두 칸에 ZIP 안 파일명(`{출처ID}.jpg`·`{출처ID}_thumb.jpg`).
  → 썸네일(…_thumb)이 엑셀·ZIP 에 없으면 비워 두고(NULL) 화면은 기존 '이미지 없음' 표시를 그대로 쓴다(사용자 결정 2026-11-11). 기존 표시: 관리자 목록 `.prod-no-img`, 관리자 상세 `.img-empty`(이미지 없음), 상품 상세 `.pd-img-empty-msg`(이미지 준비 중).

- 이미지: 엑셀 대표이미지·썸네일 칸의 파일명을 ZIP 에서 찾아(폴더 안이어도 이름으로, 대소문자 무시) 저장한다. 실제 이미지 형식(jpg·png·webp·gif)만,
  파일 이름은 내용 해시(`/uploads/syc/<해시>.<형식>`). 썸네일이 없으면 비워 두고 기존 '이미지 없음' 표시. ZIP 없이 올리면 기존 이미지는 그대로.

- 등록은 한 번의 트랜잭션(중간 오류면 DB 는 되돌림). 창을 닫아도 서버는 끝까지 처리한다.

- 테스트 엑셀 2개(`data/syccrt/syc-products-bulk-test*.xlsx`)를 위 규칙으로 다시 만듦(75칸 — 부속 6칸 추가). 같은 출처ID 라 다시 올리면 덮어씀(이미지 ZIP 없이 올려도 이미지 유지).
- 순서: DB(칸 추가 → 이름표) → 코드 배포 → 엑셀 다시 올리기.

### 8-4. 카테고리 나누기·필터 모델 코드 제거(2026-11-11 사용자 결정)

- 한 품목 안에 목록 치수 칸 구성이 다른 상품 → **별도 카테고리**('치수 칸 구성별' 선택). 10개 품목: 첫 묶음은 기존 카테고리(이름만 맞춤 7개), 나머지 13개 묶음은 같은 대분류 아래 새 카테고리(`syc-s78`~`s89`, `syc-w5`, 원래 바로 뒤 순서).
  마이그레이션: `database/20261111_syc_categories_split.sql`(이름 변경·새 카테고리) → `database/20261111_syc_axes_split.sql`(새 카테고리에 원래 이름표 복사). 마진율 칸은 넣지 않아 대분류 값(20/10)을 물려받는다.
- 상품 이동은 일괄 등록 엑셀의 분류코드(새 slug)로. 이미지 파일명은 출처ID 기준이라 그대로.
- 목록 표 나누기(8-3, `syc_list_groups`)는 그대로 둔다 — 나중에 실제 데이터에서 같은 일이 생기면 빈칸 대신 표를 나눠 보여 준다.
- 왼쪽 필터: 모델 코드 그룹 없음(치수 칸만). 목록 표의 '모델 코드' 칸은 그대로.

### 8-5. 측구수로관 합치기·모델 코드 일관화(2026-11-11 사용자 결정)

- 측구수로관 형식별 7개 카테고리(앵글미부착 A형 3개·AN형·B형 2개·Z형 주문품) → `syc-s1` '측구수로관' 하나(`database/20261111_syc_categories_merge.sql`, s2~s7 숨김).
  품명 '측구수로관', 모델 코드 = 형식(A형·AN형·B형·Z형), 옵션 = '앵글미부착/앵글부착[, 주문품], 그레이팅'.
- 모델 코드 '크기+형식'(300*400B·300A·200C)은 크기가 치수 칸에 있으므로 형식만(B형·A형·C형): 측구수로관·벤치플륨Ⅲ·환경수로관·원형사각수로관·사각수로관. 크기뿐인 코드(벤치플륨Ⅲ 200 등)는 비움.
  건널목수로관(500C·800B)은 '800'이 치수 칸(폭 795)에 없어 그대로.
- 원심력수로관: 품명 '원심력수로관' 하나, W2·S2 = 모델 코드, 무개·유개 = 옵션(코드 '250무개' 는 비움 — 호칭 D 칸에 250).

## 9. 업체 엑셀 자동 정리(2026-11-11)

업체가 다음 자료를 예전 표기(품명 '측구수로관 앵글부착 B형', 모델 코드 '300*400B', 옵션 '그레이팅 395*995*50', 나누기·합치기 전 분류코드)로 보내도
**등록 전에** 사이트 표기 원칙(품명 = 제품명만, 모델 코드 = 형식만, 옵션 = 글자만, 치수 = 칸, 분류 = 지금 카테고리)으로 고친다. 반복 수작업을 없애는 것이 목적.

### 9-1. 구조

| 층 | 파일 | 책임 |
|---|---|---|
| 규칙(데이터) | `app/syc_normalize_rules.php` | 분류 합치기·나누기 묶음(치수 칸 구성), 옵션으로 옮길 글자, 옵션 속 치수 패턴 → 칸. **카테고리를 다시 나누거나 합치면 이 파일만 고친다** |
| 엔진(순수 함수) | `app/syc_normalize.php` | 규칙을 행에 적용, 바꾼 곳마다 [행·칸·전·후·규칙] 기록. DB·파일·세션을 모름 → 테스트로 결과 고정 |
| 연결 | `app/syc_bulk.php` `syc_bulk_read_excel(…, $normalize)` | 엑셀 검증 뒤 엔진 실행, 정리 뒤 분류코드로 category_id 다시 정함. **미리보기와 등록이 같은 함수** |
| API | `public/api/admin/syc-products.php` | `stage_excel` 응답에 정리 요약(normalize), `commit` 의 `normalize`(기본 true) |
| 화면 | `public/admin-products.php` 일괄 등록 창 | 엑셀을 올리면 '자동 정리' 상자: 켜기/끄기, 규칙별 개수, 바뀌는 곳 표(앞 200곳), 경고, 전체 내역 CSV |

### 9-2. 단계(순서 고정)

1. 분류 합치기(숨긴 카테고리 → 모은 카테고리) 2. 분류 나누기(값이 있는 목록 치수 = 묶음의 어느 카테고리) 3. 옵션 속 치수 → 칸(칸이 비어 있을 때만 — 업체 값 우선, 다르면 경고)
4. 모델 코드(카테고리 단위 — 모든 코드가 '크기[+형식]' 이고 크기가 치수 칸에 있을 때만: B형·W2·옵션 글자·비움) 5. 품명(옵션 글자 → 옵션 앞, 형식과 같은 낱말 → 뺌)

### 9-3. 안전장치

- 가격·출처·이미지·규격 원문·중량·단위·업체 칸은 읽지도 바꾸지도 않음(테스트가 704행 대조).
- 근거 없는 값은 만들지 않음: 규칙에 맞을 때만 옮기고, 맞는 카테고리·칸이 없으면 그대로 두고 **경고**.
- 멱등: 정리된 엑셀을 다시 넣으면 바뀌는 곳 0(테스트).
- 창에서 끄면 엑셀 그대로 등록. 등록 결과에 정리한 상품 수 표시.

### 9-4. 검증 자료

- `data/syccrt/syc-products-bulk-test-raw.xlsx` — 예전 표기 원본(704행). 자동 정리 결과가 `products.json`(지금 데이터)과 **차이 0**(tests/functions.test.php).
- 조립식 맨홀: 원칙대로 품명에서 구체 구분을 뺌('조립식 맨홀', 옵션 '상부구체, 원형 1호') — 테스트 엑셀도 같게 다시 만듦.
- 새 규칙이 필요하면(새 업체 표기) 규칙 파일에 한 줄 추가 + 테스트 한 줄 → 미리보기에서 확인.
