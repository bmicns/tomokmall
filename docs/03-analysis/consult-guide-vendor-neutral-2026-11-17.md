## 2. 바꾼 것

1. **현재 등록 상품 목록(새)** — `consult_catalog_section($categoryKey)`
   - 상담 품목(그레이팅·배수관·맨홀·수로관·보도블록 — `rag_detect_category` 키) → 공통 분류 품명(`categories.name`)을 **자재 일반 명칭 규칙**(`CONSULT_KIND_CATEGORY_RULES`, 몰드·집게·소켓 등 부속 제외)으로 고른다.
   - 그 품명의 **판매 중 상품**(`products.is_active = 1` — 모든 업체, S20 공통 분류)을 읽어 품명별 상품 수·업체 수(`external_source` 종류)·하중 표기(대형차용·승용차용·보행자용·하중 표기 없음 — 도구와 같은 판정)를 만든다. 상품 많은 순 25개까지.
   - 규칙: 검색어는 목록의 품명으로 / 목록에 없는 품명·재질은 '아직 등록되지 않음 → 견적요청하기' / 하중 등급·톤수(T-25 등)를 지어내지 않음 / '하중 표기 없음'은 차량 통행 적합이라 하지 않음 / 업체 이름은 말하지 않음.
   - 가격 칸은 읽지 않는다. DB 조회 실패면 이 구역을 넣지 않는다(고정 안내만으로 동작). 판매 상품이 없으면 '없음 → 견적요청하기'만.
   - 업체가 자재를 일괄 등록·활성화하면 **코드·문장 수정 없이** 다음 상담부터 목록에 들어간다.
2. **고정 프롬프트에서 업체(케이토목) 상품명 제거** — `app/rag.php`
   - '토목몰 하중 등급 구분(상품명 — 등급 표기 없음=보행자용, 중하중=승용차, 안전중하중=트럭·버스)' → '확인된 하중 등급(도구 결과의 load_grade·load_check·load_basis)'.
   - [그레이팅] '하중 등급(카탈로그 3단계: 그레이팅수로용·중하중·안전중하중)' → 하중 이름을 검색어에 넣지 말고 `traffic` 으로 넘김, 도구가 표기된 등급으로 거름, 표기 없으면 '하중 확인 필요'.
   - 검색어 예 '그레이팅 수로용 중하중'·'맨홀 우수 중하중' → '그레이팅 수로용'(+ `traffic`)·'맨홀 우수'. 예시 문장 '그레이팅수로용은 … 보행자용' → 업체 이름 없는 문장.
3. **기존 상담 가이드 행(`category_consult_guide`)은 읽지 않는다** — 케이토목 상품명 기준 고정 문장('중하중그레이팅 시리즈', '플라스틱 제품 절대 추천 금지', 근거 없는 '주요 관경' 등)이라. **행은 DB 에 그대로**(지우지 않음). 되돌리기: `rag_build_prompt` 에서 `rag_load_consult_guide()` 를 다시 붙인다(함수 유지).
4. **하중 이름 규칙을 업체별로** — `ai_grating_load_class($name, $tiered)`
   - '중하중'·'안전중하중' 표기는 어느 업체든 그대로 승용차용·대형차용.
   - '표기 없는 그레이팅 = 보행자용'은 상품명에 하중 단계를 붙이는 업체(같은 출처에 '중하중' 상품이 있는 업체 — 지금은 케이토목)에만. 그 밖의 업체는 '등급 모름' → 차량 통행이면 '하중 확인 필요'(낮은 등급으로 버리지도, 맞다고 하지도 않음), 보행자면 판정하지 않음.
   - 출처를 모르면(기존 호출·테스트) 기존과 같다. 케이토목 상품의 판정·검색 결과는 바뀌지 않는다.

## 3. 바꾸지 않은 것

- DB 구조·데이터(가격 포함) — 변경 없음. `category_consult_guide` 행 그대로.
- 도구의 하중 필터·치수 확인·80T 규칙·법령 근거·수량 계산.
- 상담 품목 감지(`rag_detect_category`) — 5개 품목 + 기타. 기타 자재(볼라드 등)는 아직 '현재 등록 상품' 목록이 없다(2차 과제).
