## 2-1. 탈퇴 동의 체크·탈퇴 사유 (사용자 결정 2026-11-27)
- **'탈퇴' 글자 입력 → 동의 체크**: '위 안내 사항을 모두 확인했으며, 회원 탈퇴에 동의합니다. (필수)'. 비밀번호 확인은 그대로. API 는 `agree === true`(JSON 참 값)만 받는다.
- **탈퇴 사유(선택)** 7개 — 번호는 DB 에 저장되므로 바꾸지 않고, 새 사유는 뒤 번호로 더한다(`PRIVACY_WITHDRAW_REASONS`): 1 상품 종류가 부족함 · 2 가격이 맞지 않음 · 3 배송·운반이 불편함 · 4 공사·현장이 끝나 이용할 일이 없음 · 5 사이트 이용이 불편함 · 6 개인정보가 걱정됨 · 7 기타. 문구는 디자인 시안 '회원 탈퇴 — 일반 쇼핑몰형 참고안'과 같다.
- **남기실 말씀(선택, 300자)**: 저장 전에 이메일·전화번호(하이픈 있음·없음·지역번호)·사업자등록번호(하이픈 형식) 모양을 지운다(`privacy_scrub_text`, 빠른 상담 사진 읽기와 같은 규칙에 하이픈 없는 휴대전화를 더함). 이름처럼 모양으로 알 수 없는 정보는 지우지 못하므로 화면에 '회원 정보와 연결하지 않습니다. 적으신 전화번호·이메일 등은 지우고 저장합니다' 안내.
- **저장 = 1번 방식(회원과 연결 없는 별도 표)**: `withdraw_reasons`(id·사유 번호·말씀·회원 종류·날짜). 회원 id·이메일·시각은 두지 않아 탈퇴 계정 행과 이어 볼 수 없다. 탈퇴 처리와 같은 트랜잭션(사유·말씀이 둘 다 비면 행을 만들지 않음). 표가 없으면 사유 없이 탈퇴만 처리.
  - 다른 방식(검토 후 고르지 않음): 2번 = 탈퇴 계정 행(`users`)에 사유 칸 추가 — 계정 행과 이어져 개인정보로 볼 여지가 크고 처리방침에 항목·기간을 따로 적어야 함.
  - 일반 쇼핑몰도 계정 행은 개인정보를 지운 채 남기고(주문 등 보관 기록과 연결), 탈퇴 사유는 통계용으로 따로 둔다는 판단(11-27 사용자 대화).
- **보관**: 기한 없이 보관, 자동 정리 없음. 관리자 화면 **'탈퇴 사유'**(`/admin-withdraw-reasons.php`, 관리자 메뉴 운영 아래) — 사유별 건수·목록·한 건씩 삭제(두 번 눌러 확인, `api/admin/withdraw-reasons.php`, 관리자만).
- 처리방침: 사유·말씀은 회원과 연결하지 않고 연락처 모양을 지워 저장하므로 지금 방침(회원 정보 = 탈퇴 때 파기)과 어긋나지 않는다고 봄. 말씀에 이름 등이 남을 수 있어 방침 제1조에 한 줄을 더할지는 사용자 결정(11-27 보고).
- DB: `database/20261127_withdraw_reasons.sql`(새 표, 가격 칸 없음) · 되돌리기 `…_rollback.sql`. 순서: SQL → 코드 배포.
- 테스트: `php tests/privacy.test.php`(로컬 _test DB, 41개 — 동의 체크·없는 사유·300자·말씀 지우기·연결 칸 없음·관리자만 삭제).
