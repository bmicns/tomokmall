# AI 상담 → 견적 → 주문 연결 점검 (2026-10-29)

방법: 코드 추적(file:line) + 로컬 서버·테스트 DB(MySQL 8.0)에서 브라우저 실행. AI 답변은 목업(실제 검색 도구 결과를 카드로), 장바구니·견적 화면·견적 접수 API 는 실제 코드로 실행했다. 실제 GPT-4o 응답은 쓰지 않았다.

## 1. 단계별 상태

| 단계 | 구현 | 상태 |
|---|---|---|
| 쉬운 질문 | `public/chat.php` → `rag_process()` (비회원 가능) | 연결됨 |
| 용도·조건 확인 | 프롬프트 카테고리별 필수 항목, 면적은 가로×세로 계산 | 연결됨 |
| 적합 상품 추천 | `search_products` → `product_cards` → 비교표 | 연결됨 — 이번에 **고르는 기준·상세 링크·치수만 보이는 규격** 추가 |
| 면적 기준 수량 | `ai_estimate_quantity` → 권장 수량이 수량 칸 기본값 | 연결됨 |
| 여러 상품 가격 비교 | `queries[]` 비교, 예상 자재비 최저~최고 요약 | 연결됨 |
| 견적 담기 | 카드 '견적추가' → `/api/cart.php`, 왼쪽 견적서 패널 | **수정 전 끊김(999개 초과)** → 수정 |
| 견적 요청 | `/estimate.php` → `/quote.php` → `estimate_create` | 연결됨 — 접수 번호 표시 추가, 상태값 문제 수정 |
| 주문·결제 | `public/api/order.php` | **끊김** — 이를 부르는 화면 없음, 견적과 연결 칸 없음, 결제 URL 미구현 |

## 2. 이번에 고친 것 (작은 연결 문제만)

| 문제 | 영향 | 수정 | 확인 |
|---|---|---|---|
| 카드 수량 상한 9,999 인데 장바구니 API·견적 화면은 999 | 200㎡ 점토블럭(권장 7,628개)처럼 큰 면적은 '견적추가'에서 오류 → 진행 불가 | API·견적서 패널·견적 화면 상한 9,999(AI `add_to_cart`·즉시견적과 같음), 누적 담기도 9,999 상한 | 브라우저: 7,628개 담기 → 견적 화면 7,628 → 접수 성공 |
| 새 견적이 `PENDING` 으로 저장될 수 있음 | `alter_estimates_v2.sql` 이 기본값을 PENDING 으로 바꾸는데 직원·관리자·내 견적 화면은 REQUESTED 기준 → **새 견적이 '접수됨' 탭에 안 보임** | 견적 생성 때 상태를 `REQUESTED` 로 명시(v1·v2 ENUM 모두에 있는 값, DB 변경 없음) | 테스트 DB(v2 적용): 수정 전 PENDING → 수정 후 REQUESTED |
| 비교표 "회원가는 견적서에서 확인" | 견적서도 판매가(b2c)를 써서 사실과 다름 | "최종 금액은 견적 요청 후 회신으로 안내" | 화면 확인 |
| 접수 후 번호 없음 | 고객이 문의할 기준이 없음 | "(접수 번호 N)" 표시, 로그인 회원은 '내 견적 보기' 링크 | 브라우저 3개 크기 |
| AI 가 담을 때 수량 1 가능 | 프롬프트에 권장 수량 지시 없음 | add_to_cart quantity = 권장 수량(고객이 말하면 그 수량) | 프롬프트 기준값 테스트 |
| 모바일 비교표 가로 스크롤 | 360px 에서 수량·'견적추가' 버튼이 화면 밖 | 640px 이하에서 상품별 세로 배치, 수량·버튼 높이 44px | 스크린샷(360·768·1280), 가로 스크롤 없음 |
| 데스크톱 수량 칸 숫자 안 보임 | 공통 input 스타일이 덮어써 칸이 34px·패딩 12px | 비교표 수량 칸 스타일 우선 적용(72px) | 측정 72px, 값 표시 |
| 카드 규격에 운반비·상차수량 등 긴 표기 | 초보 고객에게 읽기 어려움 | 카드는 치수만(`spec_size_label`), 전체 규격은 상세 페이지 | 화면 확인 |

## 3. 남은 문제 (승인·설계 필요, 영향 큰 순)

1. **견적 → 주문·결제 연결 없음** — `order.php` 를 부르는 화면이 없고, 견적 접수 때 장바구니가 비워지며, orders 에 estimate_id 가 없고 결제(PG) 미구현. 고객이 직접 주문할 수 없고 담당자 연락에 의존. → '견적 승인 → 주문 전환' 설계 필요(DB 칸 추가·PG 선택은 승인 대상).
2. **견적 상태값 ENUM 확인 필요(운영)** — 코드가 쓰는 `WORKING` 이 저장소의 어떤 SQL 에도 없음. 운영 DB 에 없으면 직원 '처리' 시 상태 변경이 실패할 수 있다. 읽기 전용 확인: `SHOW CREATE TABLE estimates; SELECT status, COUNT(*) FROM estimates GROUP BY status;`
3. **가격 등급 불일치** — AI 상담·견적서는 판매가(b2c), `public/cart.php` 는 등급가, 기업회원 b2b 는 즉시견적 경로에만.
4. 비회원 견적 조회 불가(번호만 표시), `my-estimates.php` 에 상세·다음 단계 버튼 없음.
5. 장바구니·견적서에 단위(㎡·개) 미표시, 견적서 패널 규격은 아직 전체 표기.
6. 이전 상담 이어보기(`/chat.php?sid=`)·견적 참조(`/estimate.php?ref=`) 링크가 동작하지 않음.
