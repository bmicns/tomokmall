# AI 상담 → 견적 담기 연결 점검 (2026-10-29, 범위 정정 반영)

**범위**: AI 상담의 상품 추천·수량 계산·가격 비교·견적 담기까지. **주문·결제 시스템 개발은 이번 프로젝트 범위가 아니다**(사용자 지시 — 따로 요청할 때까지 설계·개발하지 않음).

방법: 코드 추적 + 로컬 서버·테스트 DB(MySQL 8.0)에서 브라우저 실행. AI 답변은 목업(실제 검색 도구 결과를 카드로), 장바구니·견적 화면·견적 접수 API 는 실제 코드로 실행. 실제 GPT-4o 응답은 쓰지 않았다.

## 1. 단계별 상태

| 단계 | 구현 | 상태 |
|---|---|---|
| 쉬운 질문 이해 | `rag_detect_category`·`rag_road_context`, 친절 응대 원칙(먼저 답하고 꼭 필요한 질문 1~2개) | 동작 — 초보 예시 4문장 회귀 테스트 추가 |
| 용도·조건 확인 | 카테고리별 필수 항목, 면적은 가로×세로 계산 | 동작 |
| 여러 종류 추천 | `search_products` 비교(queries) → 비교표 | 동작 — 고르는 기준·상세 링크·치수만 표시 |
| 면적 기준 수량 | `ai_estimate_quantity` → 권장 수량·계산 근거(㎡ → 장수) | 동작 — '몇 개' 질문은 계산 근거 인용 규칙 |
| 예상 비용 비교 | 예상 자재비 최저~최고 요약 | 동작 — **예상 최저 표시 + cost_summary**(가격 질문은 도구 계산값만 인용) |
| 추천 이유·주의사항 | 카드 고르는 기준(두께·투수·재질·하중) | 동작 — 이유는 기준으로, 주의는 고객 조건과 맞지 않는 것만 |
| 견적 담기 | 카드 '견적추가' → `/api/cart.php`, 왼쪽 견적서 패널 → 견적 요청 | 동작(수량 상한 999 — 기존대로) |

## 2. 사용자 지시로 원복한 것

| 항목 | 원복 내용 | 확인 |
|---|---|---|
| 견적 수량 상한 | 장바구니 API·견적서 패널·견적 화면 9,999 → **999**(이전 커밋의 해당 줄만 되돌림) | API: 1,000개 → "수량은 1~999 범위여야 합니다", 999개 → 성공. 브라우저 3개 크기에서 1,000 입력 시 같은 안내 |
| 신규 견적 상태 | `estimate_create` 의 `status = 'REQUESTED'` 명시 제거 → **기존처럼 DB 기본값으로 저장**(v2 마이그레이션 적용 DB 는 PENDING) | 테스트 DB(v2 적용): 새 견적 PENDING |

## 3. 별도 보고 — 고치지 않은 불일치 (판단 필요)

1. **PENDING 과 직원·관리자 화면 불일치** — `alter_estimates_v2.sql` 은 새 견적 기본값을 `PENDING` 으로 바꾸지만, 직원 견적 화면 탭(`public/staff/index.php:10`), 관리자 상태 필터(`public/admin-estimates.php:15`), 내 견적 라벨(`public/my-estimates.php:15`)은 `REQUESTED·WORKING·SENT·APPROVED·CANCELED` 만 다룬다. 운영 DB 에 v2 가 적용돼 있으면 **새 견적이 직원 '접수됨' 탭에 보이지 않을 수 있다**(테스트 DB 에서 재현: 새 견적 status=PENDING). 또 코드가 쓰는 `WORKING` 은 저장소의 어떤 SQL ENUM 에도 없다.
   - 운영 읽기 전용 확인: `SHOW CREATE TABLE estimates;` · `SELECT status, COUNT(*) FROM estimates GROUP BY status;`
   - 지시대로 운영 스키마·직원 처리 프로세스는 바꾸지 않았다.
2. ~~카드 수량 입력(9,999)과 견적 담기 상한(999) 차이~~ → **2026-10-29 사용자 지시로 999 로 통일**(아래 5장).
3. 견적 페이지 모바일(360px) 가로 스크롤 — 견적 요청 폼의 입력칸 하나가 551px 로 넘친다(이번 변경 전에도 같음, 범위 밖이라 보고만).

## 4. 이번에 유지한 상담 개선 (원복 대상 아님)

비교표 고르는 기준·상세 링크·치수만 보이는 규격, 예상 최저 표시, 모바일·태블릿(900px 이하) 세로 카드와 44px 수량·버튼, 데스크톱 수량 칸 표시 오류 수정, 사실과 다른 '회원가는 견적서에서 확인' 문구 수정, 견적 접수 후 접수 번호 표시, AI 담기 수량 = 권장 수량.

## 5. 수량 1~999 통일 (2026-10-29 사용자 지시)

견적 담기·수량 입력은 1~999 만 허용한다. 999 초과용 안내 UI·수량 분할·대량 처리는 만들지 않는다(기존 검증 안내 "수량은 1~999 범위여야 합니다"만).

| 위치 | 변경 |
|---|---|
| AI 상품 카드 수량 칸 | max 9999 → 999. 담기 버튼은 값을 그대로 보내고 장바구니 API 가 검증(999 초과를 999 로 몰래 바꾸지 않음) |
| AI `add_to_cart` 도구 | 9999 로 잘라 담던 것 → 1~999 밖이면 담지 않고 같은 안내, 이미 담긴 수량과 합쳐 999 초과도 거부 |
| 장바구니 API `/api/cart.php` | 1~999(기존) + 이미 담긴 수량과 합쳐 999 초과 거부 |
| 견적서 패널·견적 페이지 | 999(즉시견적 모드 9999 → 999) |
| 즉시견적 API `quick-items.php`·화면(`quick_estimate_renderer.php`, `corp-home.js`) | 9999 → 999 |
| 관심상품 수량 API `favorites.php` | 9999 → 999(관심상품 수량이 견적으로 이어지므로) |
| 그대로 둔 것 | 운임 계산 API `freight-cart.php`(계산 전용, 담기 아님) |

확인: 단위 테스트(AI 담기 1,000 거부·999 담김·합계 초과 거부), 브라우저 3개 크기(카드 max 999, 권장 7,628개 카드 담기 → 기존 안내, 999 담기 → 패널·견적 페이지 999).
