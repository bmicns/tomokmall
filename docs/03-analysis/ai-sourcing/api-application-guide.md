# 공식 API·인증키 신청 안내 (2026-10-28)

조사 방법: 웹 검색 결과(제목·요약)만 사용했다. 이 작업 환경은 law.go.kr·kcsc.re.kr·standard.go.kr·data.go.kr 접속이 차단되어 신청 화면을 직접 열지 못했다.
그래서 확인하지 못한 내용은 **미확인**으로 적었다. 신청할 때 화면 안내를 우선으로 따른다.

## 2. 사용자가 직접 할 일

1. **국가법령정보 OPEN API 신청**(1순위)
   - 등록 정보: 실행할 곳의 공인 IP. 가장 간단한 방법은 **법령 대조 스크립트를 실행할 PC 의 공인 IP** 등록(운영 사이트는 이 API 를 쓰지 않음).
   - 운영 서버에서 돌릴 계획이면 닷홈 서버의 외부 IP(고정 여부 포함)를 닷홈에 문의(미확인).
   - 이 클라우드 작업 환경의 IP 는 고정이 아니고 law.go.kr 접속도 차단되어 있어 등록 대상이 아니다.
2. 발급된 OC 를 **로컬 `.env.local`** 에 입력(아래 3장). 채팅·이슈·커밋에는 넣지 않는다.
3. 등록 IP 의 PC 에서 `php scripts/legal-sources/law_api_sync.php --md=api-sync-report.md` 실행 → **보고서 파일만** 공유(보고서에는 키가 들어가지 않는다).
4. (권장) 공공데이터포털 국가표준 CSV 다운로드 → 저장소 밖 로컬 폴더에 두고 경로만 알려주기.
5. (선택) KCSC 코드 뷰어에서 KDS 44 50 25 적용 범위·블록 두께 조항 확인, 또는 작업 환경 네트워크 허용 도메인에 `kcsc.re.kr`, `codil.or.kr`, `law.go.kr` 추가.

## 3. 인증키를 안전하게 두는 곳

| 위치 | 용도 | 방법 |
|---|---|---|
| 로컬 `.env.local` (프로젝트 루트, Git 제외) | 법령 대조 스크립트 | `LAW_API_OC=발급값` 한 줄 추가. 키 이름은 `.env.example` 에만 있고 값은 비어 있음 |
| 셸 환경변수 | 1회 실행 | `read -rs LAW_API_OC && export LAW_API_OC` (화면·기록에 남지 않게 입력) 후 스크립트 실행 |
| 운영 `/app/.env` | **넣지 않아도 됨** | 웹 화면은 이 API 를 호출하지 않는다. 나중에 서버에서 자동 대조를 돌릴 때만 승인 후 추가 |

- `git status` 로 `.env.local` 이 추적되지 않는지 확인(`.gitignore` 의 `.env*` 규칙).
- 키가 채팅·커밋·로그에 노출되면 open.law.go.kr 마이페이지에서 재발급(교체).

## 5. 계정 변경(개인용 → 기업용, 2026-10-28) 점검

코드 수정 필요 여부: **없음**.
- 클라이언트(`app/law_api.php`)는 인증값을 `getenv('LAW_API_OC')` 로만 읽는다. 계정 종류·이메일·IP 를 코드에 넣은 곳이 없다.
- 법령 검증 데이터(`api_targets.json` 기준값, `verified_clauses.json`, SQL 초안)는 계정과 무관하므로 그대로 둔다.

이번에 보강한 것(`law_api_sync.php`):
- `--check` 연결 점검 모드를 추가했다. 법령·행정규칙 검색을 1회씩 호출해 정상/실패와 사유만 보여 주고, OC 값은 출력하지 않는다.
- 셸·Windows 환경변수에 예전 OC 가 남아 있으면 `.env.local` 의 새 값이 무시된다. 두 값이 다르면 경고한다(값은 출력하지 않음).
- "사용자 정보 검증에 실패" 응답을 인증 실패로 구분한다. 이때 확인할 것은 OC·등록 IP/도메인·승인 상태다.

새 계정에서 확인할 설정(사용자, open.law.go.kr 마이페이지). 등록 정보는 계정마다 따로이므로 개인용 계정의 설정이 기업용으로 넘어오지 않는다.

| 항목 | 확인 내용 | 필요 여부 |
|---|---|---|
| OC 값 | 마이페이지의 인증값과 `.env.local` 의 `LAW_API_OC` 가 같은지(앞뒤 공백·따옴표 없이) | 필수 |
| 서버 IP | 대조 스크립트를 실행하는 **PC 의 공인 IP** 를 새 계정에 등록. 가정·사무실 인터넷은 IP 가 바뀔 수 있음 → 실패하면 현재 공인 IP 재확인 | 필수(등록 방식은 2차 자료 기준) |
| 도메인 | 운영 사이트(tomokmall.dothome.co.kr)는 이 API 를 호출하지 않으므로 지금은 불필요. 나중에 서버에서 자동 대조를 돌릴 때만 서버 IP·도메인 추가(승인 후) | 지금은 불필요 |
| API 이용 권한 | 쓰는 API 는 **법령 목록·본문(target=law)** 과 **행정규칙 목록·본문(target=admrul)** 두 종류. 새 계정에서 이 둘을 활용 신청하고 승인됐는지 확인(정확한 메뉴 이름은 미확인) | 필수 |
| 이전 개인용 OC | 더 쓰지 않으면 셸·Windows 환경변수, 다른 PC 의 `.env.local` 에서 지운다. 개인 계정 해지는 선택 | 권장 |
| 호출량 | 대조 1회에 약 32건(16문서 × 검색·본문) + 0.5초 간격. 기업용 한도는 미확인 | 참고 |

실행 순서(등록한 IP 의 PC 에서):
1. `php scripts/legal-sources/law_api_sync.php --check`
   - 두 줄 모두 '정상'이면 새 OC 가 동작하는 것이다.
   - '인증 실패'면 위 표의 OC·IP·권한을 확인한다.
   - '연결 실패'면 네트워크 문제다.
   - '경고: 셸 환경변수…'가 나오면 예전 OC 환경변수를 지우고 새 터미널에서 다시 실행한다.
2. 정상이면 `php scripts/legal-sources/law_api_sync.php --md=api-sync-report.md` 로 전체 대조를 하고 보고서를 공유한다. 16문서 일치가 그대로인지 확인하는 용도다.

**전환 결과(2026-10-28): 완료.**
- `--check` 결과: 인증값 출처 `.env.local`, 법령·행정규칙 모두 정상, 인증 실패·연결 오류 없음.
- 전체 대조: 16개 문서·감시 조문 25개 모두 일치. 보고서는 `legal-sources/api-sync-report-2026-10-28-company.md`.
- 개인용 계정 결과와 같으므로 검증 데이터는 바꾸지 않았다. 대조 기록(`api_targets.json` 의 `recheck_company_oc`)만 추가했다.
