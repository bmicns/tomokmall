## 1. 프롬프트 생성 분리 (`app/rag.php`)

- `rag_build_prompt(array $messages)` 를 새로 만들었다. 카테고리 감지, 상담 가이드, 사내 문서, 장소 판정, 법령 근거, 시스템 프롬프트를 묶어 반환하고 API 는 호출하지 않는다.

## 6. 상담 품질 보완 (2026-10-29, 실제 GPT-4o 테스트 전)

### 6-1. '블록' 카테고리 감지 (`app/rag.php`)

- 기존 감지어(보도블록·인터로킹·보차도 등)는 그대로 두고, **'블록·블럭'만 쓴 경우**를 추가했다.
  - 바닥 포장 문맥(깔기·포장·바닥·마당·주차·진입로·인도·보도·차도·도로·정원·두께·NNT·mm·㎡·차량 등)이 있으면 보도블록(pavement) 상담 가이드를 쓴다.
  - 호안·옹벽·속빈·조적·축조·담장·벽체·'쌓' 이 있으면 쌓는 블록으로 보고 보도블록으로 분류하지 않는다(마당 담장 쌓기 포함).
  - 두 단서가 모두 없으면(예: '블록 얼마예요?') 카테고리를 정하지 않고, 프롬프트에 **블록 종류 확인 구역**을 넣는다 — "바닥에 까는 포장용인가요, 담장·옹벽·화단처럼 쌓는 용도인가요? 설치 장소도 알려 주세요."
  - 맨홀·관·수로관·그레이팅 감지는 기존 순서대로 먼저 판정한다(예: '맨홀 블록' → 맨홀).
- 결과: 7개 시나리오 모두 보도블록 가이드·사내 문서가 들어간다(수정 전에는 1번만). 장소 판정·법령 근거 범위는 수정 전과 같다.

### 6-2. 100mm 포장 블록 부재 처리 (`app/ai_tools.php`, 상담 화면)

- 포장 블록 + `spec_strict` 검색에서 맞는 두께가 하나도 없으면(단일·비교 검색 모두):
  - 도구 안내: "'…'은(는) 규격 100mm 제품이 없습니다(현재 등록 상품 기준). 기준보다 얇은 다른 두께는 대체품으로 권하지 않습니다. 발주처 설계도서·시방서의 블록 규격을 확인해 주세요 — 해당 규격은 별도 견적이 필요합니다."
  - 상담 화면 카드(`spec_unavailable`): "두께 100mm 포장 블록 — 현재 등록된 적합 상품이 없습니다".
- 공공도로 안내 구역(근거가 있을 때만 들어가는 구역)에 "맞는 제품이 없으면 적합 상품 없음을 분명히 알리고 80T·60T 를 대체품으로 권하지 않으며, 설계도서 규격 확인·별도 견적 안내" 1줄을 추가했다.
- **상품을 만들거나 DB 에 넣지 않았다.** 포장 블록이 아닌 품목(PE관 등)과 결과가 있는 규격 검색(80T 등)은 기존 동작 그대로다.
- 기존 UI 연결 검토: '견적요청하기'는 장바구니에 상품이 있어야 활성화되고, 상품 없이 문의를 남기는 창구는 없다. 그래서 "담당자가 연락드린다"는 약속은 넣지 않았다(지킬 수 없는 안내). 별도 견적 문의 창구(연락처 남기기 등)는 **새 기능 제안**이다 — 화면·DB 변경이 필요해 승인 후 진행.

### 6-4. 실제 GPT-4o 핵심 3개 — 자동 점검 보강

`consult-scenarios.php --core` 의 공공도로 시나리오는 추천 상품이 100mm 가 아니면 **실패**, 상품도 '적합 상품 없음' 카드도 없으면 **확인 필요**로 표시한다. 결과 문서에 카드 표시 여부를 적는다. 자동 점검은 보조이고, 답변 원문(80T·60T 대체 추천 여부, 출처 인용)은 사람이 확인한다.

## 7. 실제 GPT-4o 핵심 3개 — 1차 실행 분석 (2026-10-29, 사용자 PC)

원본: [`gpt4o-core-2026-10-29-run1.md`](gpt4o-core-2026-10-29-run1.md). 이 장의 ③ 은 **실제 GPT-4o 응답**, 원인 확인·수정 검증은 클로드가 테스트 DB·목업으로 한 것이다(실제 API 호출 아님).

### 7-1. 실제 답변 검토 (마지막 턴만 기록돼 있음)

| 확인 항목 | 공공도로 차도 | 차량 진입 공공 보도 | 개인 마당 |
|---|---|---|---|
| 기준 수치·출처 | 2턴에 "100mm 블록" 방향은 맞음. KDS/KCS 인용은 **1턴 원문이 기록되지 않아 확인 불가** | 2턴에 "80mm 이상"만, 보도 지침 적용 조건(4t 이하 차량 출입부)·출처 없음. 1턴 확인 불가 | 사내 80T 안내, 공공도로 출처 없음 — 적절 |
| 부적합 상품 추천 | 80T·60T 추천 없음 | — | — |
| 상품 검색·카드 | **검색 안 함**("찾아 드릴게요. 잠시만 기다려 주세요"로 끝남) → 카드 없음 | **검색 안 함**(면적까지 받고 "추가 정보가 필요하신가요?"로 끝남) | '보차도블록'·'중하중 인터로킹'으로 검색 → 0건 → '적합 상품 없음' 카드 |
| 허위 법령·규격·상품 | 없음 | '중하중 보차도블록' 언급 — 등록 상품명이 아니라 사내 가이드의 분류명 | "별도로 문의 주시면 찾아드리겠습니다" — **처리할 수 없는 약속**(상품 없이 문의 받는 창구 없음). 사유지인데 '발주처 설계도서' 안내 |

자동 점검의 '통과'(개인 마당)는 잘못된 판정이다. 80T 포장 블록이 등록돼 있는데 '적합 상품 없음' 카드가 나온 경우를 통과로 처리했다.

### 7-2. 원인 — 상담 흐름 vs 테스트 환경·스크립트

| 원인 | 구분 | 근거 |
|---|---|---|
| ① 검색하겠다고만 하고 도구를 호출하지 않고 끝남(공공도로) | **상담 흐름** — 실제 화면에서도 손님이 결과 없이 기다리게 된다 | 마지막 턴 원문 |
| ② 필수 항목(장소·차량·면적)을 다 받았는데 되묻고 끝남(보도) | **상담 흐름** | 시나리오 2턴에 면적·차량 모두 있음 — 시나리오 문제 아님 |
| ③ 사유지 80mm 검색 0건 | **테스트 환경** — 사용자 PC 가 MariaDB 10.4(ngram 없음). 같은 MariaDB 를 재현하니 '인터로킹 블록' 80T 0건, 'PE 배수관' → 파형강관 등 한글 검색이 운영(MySQL 8.0)과 크게 다름. 같은 검색을 MySQL 8.0 에서 하면 인터로킹 80T 등 3건 | MariaDB 10.4.32 컨테이너 재현 |
| ④ 사내 가이드 분류명('보차도블록' 등)으로 검색 → 0건이면 대안 없음, '문의 주시면' 약속 | **상담 흐름**(일부는 6장 안내 문구가 사유지에도 '설계도서·별도 견적'을 붙인 탓) | 도구 결과 재현 |
| ⑤ 마지막 턴만 기록·카드만 있으면 통과 | **테스트 스크립트** | 1턴 근거를 판단할 수 없음 |

### 7-3. 수정 (필요한 부분만)

- `app/rag.php`
  - 공통 규칙 4줄: 필수 항목 확인 후 되묻지 말고 검색 · '찾아 드릴게요'만 하고 끝내지 않기 · 도구의 alternatives 로 재검색 · 처리할 수 없는 문의·연락 약속 금지(견적요청하기 버튼 안내는 허용).
  - `rag_process`: 도구를 한 번도 안 쓰고 "찾아/검색해 드릴게요·잠시만 기다려"로 끝난 응답이면 그 문장을 버리고 `search_products` 를 1회 강제 호출(반복 없음, 호출 한도 +1). 여러 단계 답변은 줄바꿈으로 잇는다.
- `app/ai_tools.php`: 엄격 두께 검색이 0건일 때 **같은 두께로 등록된 포장 블록이 있으면**(DB 종류와 무관한 조회) '적합 상품 없음' 카드 대신 그 이름을 `alternatives` 로 돌려 재검색하게 한다. 같은 두께가 하나도 없을 때(100mm)만 기존 카드·설계도서·별도 견적 안내. 더 얇은 두께는 어느 경우에도 권하지 않는다.
- `scripts/testdb/consult-scenarios.php`
  - 턴마다 답변·인용 근거·상품 카드·적합 상품 없음 카드를 모두 기록하고, 근거·수치는 전체 턴에서 판정.
  - 판정 보강: 그 두께 상품이 등록돼 있는데 '적합 상품 없음' → 실패. 공공도로는 KDS/KCS 인용 + 100mm, 보도는 보도 지침 인용 + 80mm 가 있어야 통과.
  - 사전 점검에 상품 검색 환경 확인('인터로킹 블록' 80T) — MariaDB 등 0건이면 `--core` 를 중단(`--skip-product-check` 로 답변만 확인 가능).
  - `--only=public_road,public_sidewalk` 로 일부 시나리오만 재실행.
- 상품·DB 데이터 변경 없음. 80T 문구 3개 그대로.

검증(클로드, 실제 API 아님): 단위·통합 테스트 전체 통과. 목업 OpenAI 서버로 `rag_process` 루프와 `consult-scenarios.php --core` 전체 흐름 확인 — 약속만 한 응답 → 강제 검색 → 100mm 카드, 보도 80T 4종, 질문으로 끝나는 응답은 그대로, 검색 후에는 강제 호출 없음.

### 7-4. 재테스트 — MySQL 8.0 테스트 DB 필요

XAMPP 의 MariaDB 로는 상품 추천을 점검할 수 없다. Docker Desktop 이 있으면 MySQL 8.0 테스트 DB 를 따로 띄운다(로컬 전용, 127.0.0.1 에만 열림, 테스트용이라 root 비밀번호 없음). Git Bash 에서:

```
git pull origin claude/loving-gates-surk6e
docker run -d --name tomokmall_test_mysql8 -e MYSQL_ALLOW_EMPTY_PASSWORD=yes -p 127.0.0.1:3308:3306 mysql:8.0
# 약 30초 뒤 (비밀번호 질문에는 Enter)
MYSQL_CMD="docker exec -i tomokmall_test_mysql8 mysql -h127.0.0.1 -uroot" bash scripts/testdb/setup-local-test-db.sh
export DB_HOST='127.0.0.1;port=3308' DB_NAME=tomokmall_test DB_USER=root DB_PASS=
/c/xampp/php/php.exe scripts/testdb/consult-scenarios.php --check-only --core --with-public-road
/c/xampp/php/php.exe scripts/testdb/consult-scenarios.php --core --with-public-road --md=consult-result-2.md
```

- 사전 점검에 "상품 검색('인터로킹 블록' 80T): 2건 — 운영과 같은 검색 환경" 이 나와야 한다.
- 공공도로·보도 2개만: 마지막 명령에 `--only=public_road,public_sidewalk`. 개인 마당도 7-1 문제(문의 약속·MariaDB 0건)가 있어 3개 모두 다시 하는 것을 권한다(약 0.15~0.2달러).
- Docker 가 없으면 MySQL 8.0 Community Server(Windows) 를 3308 포트로 설치해 같은 방법으로 쓴다.
- 이 판은 클로드 환경에서 위 절차(컨테이너 → 설정 스크립트 → `--check-only --core`)를 그대로 실행해 통과를 확인했다.

### 7-5. V21·V22

비활성 유지. 1턴 근거 원문이 기록되지 않았고, 공공도로·보도 모두 상품 검색·카드까지 확인되지 않았다. 2차 실행에서 두 시나리오가 근거(출처 인용)·상품(100mm 없음 카드 / 80T 표)·답변 원문 모두 확인되면 로컬 활성화를 판단한다.
