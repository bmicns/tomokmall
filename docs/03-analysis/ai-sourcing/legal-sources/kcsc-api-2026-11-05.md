# 국가건설기준센터(KCSC) OpenAPI — 인증키 설정과 조회 도구 (2026-11-05)

> 목적: 법령 미러에는 고시문만 있고 본문이 없던 설계기준(KDS)·표준시방서(KCS)를 공식 API 로 읽는다. 대상은 하수관로공사·관로·맨홀·보강토 옹벽·비탈면·호안 등이다. 상담 공백 자재(관·수로관·맨홀·보강토)의 '공사 조건' 근거로 쓴다.
> 사용자가 2026-11-05 인증키를 발급하고 클라우드 환경 변수 `KCSC_API_KEY` 로 설정했다. 같은 날 확인 결과는 다음과 같다.
> - `--check`: 목록 3,581건(SMCS 853·KCS 776·KDS 563·LHCS 544·EXCS 328 등), 응답 형식은 공개 연동 코드 문서와 같다.
> - `--code='KCS 61 40 10'`: 절 296개를 해석했고 낱말 검색도 됐다.
> - **주의**: User-Agent 에 한글이 들어가면 HTTP 502 가 난다 → ASCII 로 고쳤다(`KCSC_USER_AGENT`).

## 1. 인증키 설정 (값은 채팅에 쓰지 않는다)

| 어디서 | 방법 |
|---|---|
| 클라우드 세션(이 환경) | 세션 제목줄의 클라우드 환경 메뉴 → **Edit** → **Network secrets**(앱에 따라 'API credentials') 칸이 있으면 거기에, 없으면 **환경 변수**에 이름 `KCSC_API_KEY`, 값 = 발급 키 → 저장. **새 세션**부터 적용된다(지금 세션에는 들어오지 않음). |
| 사용자 PC | 저장소 루트 `.env.local` 에 `KCSC_API_KEY=발급키` 한 줄. `.env.local` 은 Git 제외. |

- 도구는 `getenv('KCSC_API_KEY')`(없으면 `.env.local` 의 같은 이름 줄)만 읽는다. 키는 출력·저장하지 않고, 오류 메시지에서도 `***` 로 가린다.
- 운영 서버(`/app/.env`)에는 넣지 않는다. 웹 화면은 KCSC 를 부르지 않는다.
- 네트워크: 이 환경에서 `https://kcsc.re.kr/OpenApi/…` 접속은 확인했다(2026-11-05). 키 없이 부르면 값이 모두 null 인 1건이 온다 — 도구가 '키 오류'로 멈춘다.

## 2. 조회 도구 `scripts/legal-sources/kcsc_fetch.php`

```bash
php scripts/legal-sources/kcsc_fetch.php --check
```

```bash
php scripts/legal-sources/kcsc_fetch.php --find='하수,관로' --type=KCS --out=/저장소/밖/폴더
```

```bash
php scripts/legal-sources/kcsc_fetch.php --code='KCS 61 40 10' --grep=토피 --out=/저장소/밖/폴더
```

- 요청 형식(목록 `OpenApi/CodeList?key=`, 본문 `OpenApi/CodeViewer/{KDS|KCS}/{6자리}?key=`, JSON)은 공식 문서 대신 공개 연동 코드 두 곳에서 확인했다(sinmb79/KCSC-MCP, lhs1152-lgtm/kcsc-design-mcp). 키를 넣은 첫 실행에서 실제 응답 모양을 다시 확인하고, 다르면 `kcsc_lib.php` 를 고친다.
- 원본 응답은 `--out` 폴더(저장소 밖만)에 둔다. 기준 본문을 저장소에 넣거나 상담에 그대로 재게시하지 않는다.
- 새 근거는 자동으로 넣지 않는다. 조항을 읽고 요지만 `verified_clauses.json` 에 V39~ 로 기록한다(적용 조건·주의·출처 URL). 그다음 기존 순서(로컬 상담 연결 시험 → 운영 등록·활성화 승인)를 따른다.
- 테스트: `php tests/kcsc_api.test.php`(가상 응답으로 해석·키 가림·저장소 밖 출력·키 없음 안내).
