# 2-1단계 병행 전략 — 공식 법령 API 우선 + 기존 수집 유지 (2026-10-28)

- 법령·행정규칙은 **국가법령정보 공동활용 OPEN API**(법제처)로 원문·조문·시행일·개정 정보를 자동 수집·대조한다. 인증키(OC) 발급 전에는 **모의 응답**으로 코드·테스트를 완성해 두었다.
- API 로 얻을 수 없는 KDS·KCS 본문, KS, 별표 내용은 기존 방식(공식 고시·KCSC·e나라표준인증·공식 대체 배포처)으로 계속 수집한다. 비공식 미러·검색 자료는 **참고자료**로만 쓰고 확인 수준을 따로 둔다.
- 기존 결과(39건 판정, `verified_clauses.json` 12건, 로컬 연결 11건, 상담 검색·근거 카드)는 그대로 유지. 원문 미러는 API 대조 전까지 **기준값(보조 자료)**.
- 어떤 수집 결과도 자동 활성화하지 않는다. API 대조 결과 개정·차이가 나오면 **비활성 권고 SQL 초안**만 만든다.

## 2. API 연동 구현

| 파일 | 역할 |
|---|---|
| `app/law_api.php` | 요청 URL(OC·type=XML), HTTP(타임아웃 15초·리다이렉트 안 따름), XML 파싱(검색·법령 본문·행정규칙 본문·별표·부칙), 오류 판별(`<result>실패`·결과 없음·인증 실패 HTML), 조문 정규화·해시, 기준값 비교(`same`/`pending`/`amended`/`changed`/`missing`), 조치 문구. 외부 엔티티 차단(XXE). DB·웹 화면에서 쓰지 않음 |
| `scripts/legal-sources/build_api_baseline.php` | 원문 미러에서 감시 조문 해시·공포번호·시행일·별표 제목을 계산해 `api_targets.json` 기준값으로 저장(조문 전문은 저장 안 함) |
| `scripts/legal-sources/law_api_sync.php` | 검색 → 현행 판 선택 → 본문 → 기준값 대조 → 보고서(md·json) + 재검토 대상 **비활성 권고 SQL 초안**(첫 줄 안전장치). DB 접속 없음 |
| `tests/law_api.test.php` + `tests/fixtures/law_api/` | 모의 응답 50개 검사(키·네트워크·DB 불필요) |

비교 상태와 할 일:

| 상태 | 뜻 | 할 일(자동 처리 없음) |
|---|---|---|
| 일치 | 공포번호·시행일·감시 조문 해시가 기준값과 같음 | `verify_source` 에 "법제처 OPEN API 대조(날짜)" 기록 → 미러 확인 근거를 API 확인으로 갱신 |
| 시행 예정 개정 | 새 판의 시행일이 아직 안 옴 | 시행일까지 기존 근거 유지, 시행일에 재대조 (예: 장애인등편의법 제21116호 2026-11-12 시행) |
| 개정됨 | 번호·시행일이 바뀌고 시행 중 | 사람 재검토. 활성 근거면 비활성 권고 SQL(`--sql`) |
| 내용 차이 | 같은 판인데 조문 해시가 다름 | 형식 차이인지 실제 차이인지 사람 확인 |
| 조문 없음 / 검색 안 됨 | 조문 이동·삭제, 명칭 변경·폐지 | 사람 확인 |

## 4. 하나의 RAG 로 통합 — 관리 항목과 갱신 흐름

- 관리 항목(이미 반영): 기준명(`source_name`), 조항(`source_ref`), 시행일(`effective_date`), 공포·개정일(`revised_date`), 출처(`source_url`·`verified_by`), 적용 대상(`applies_to`), 검증 상태(`verify_level`·`review_status`·`legal_status`).

- 개정 갱신 흐름: `law_api_sync.php`(주기 실행) → 보고서 → 사람 검토 → `verified_clauses.json` 수정 → `build_verified_sql.php` 로 SQL 초안 재생성 → 승인 후 적용. 개정 감지 시에는 비활성 권고 SQL 만 자동 생성.

### 7-5. API 대상 17건과 대조 문서 16건의 차이

17건은 **후보 기준명**, 16개는 **API 로 받는 문서(법령·고시) 단위**라 1:1 이 아니다. 17건 모두 16개 문서 중 하나 이상으로 대조됐고, 대조에서 **빠진 후보는 없다**. 다만 대조가 보증하는 범위가 다르다:

## 8. 80T 사내 기준과 공식 기준의 맥락 분리 · 4차 원문 검증 (2026-10-28)

### 8-1. 공식 기준별 적용 대상 (원문 그대로, 범위 확대 없음)

| 맥락 | 공식 기준 | 블록 두께 | 적용 대상(원문) | 상담 근거 |
|---|---|---|---|---|
| 공공도로 **차도** | KDS 44 50 25:2026 · KCS 44 50 25:2026 | **최소 100mm**. 표준단면 표층 100mm(AADT 1,000대/일 이하)·120mm(2,000~4,000대/일), AADT 4,000 초과·중차량 15% 초과·설계속도 60km/h 초과는 역학적 설계. - "도로법 제10조 도로"는 국가·지자체가 노선을 지정한 도로다. 사유지 마당, 아파트 단지 안 도로, 민간 진입로는 이 목록에 들지 않는다. 다만 단지 안 도로가 법정도로로 지정됐는지는 상담에서 확정할 수 없어 '발주처·설계도서 확인'으로 안내한다.
- 100mm 는 "최소값"이다. 100/120mm 는 노상 CBR 5 기준의 표준단면값으로, AADT 1,000 이하는 100mm, 2,000~4,000 은 120mm 다. 설계 결과에 따라 더 두꺼워질 수 있고, 최종 값은 발주처 설계도서가 정한다.
