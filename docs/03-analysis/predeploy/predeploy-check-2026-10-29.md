## 1. 운영 DB ↔ 최신 코드 호환성

### 1-1. 이번 배포가 DB 에 하는 일
- `scripts/predeploy-db-check.sh 516950f HEAD`: 변경된 PHP 에 **쓰기 SQL 추가 없음**, 새로 참조하는 테이블은 모두 저장소 SQL 에 정의됨.
- `database/20261029_external_products.sql` 이 새로 있으나 **운영에 반영하지 않는다**(로컬 테스트 전용 — 없어도 동작, 2장).
- 운영 DB 구조를 바꾸지 않으므로 **DB 먼저 반영 → 코드 배포** 순서가 필요 없다.

### 1-2. 코드가 요구하는 구조 — 운영 확인용 읽기 전용 SQL
[`prod_schema_check_readonly.sql`](prod_schema_check_readonly.sql) — `information_schema` SELECT 1문장(데이터 값 없음, 승인 없이 가능한 조회).
- 실행: 닷홈 phpMyAdmin → 운영 DB 선택 → SQL 탭에 전체 붙여넣기 → 실행 → **결과 표 전체**를 전달.
- 판정: `필수` 가 모두 `있음` 이면 코드 배포 가능. `필수 … 없음` 이 하나라도 있으면 **배포 보류**하고 원인 확인.
- 로컬 검증(같은 SQL):

| DB | 필수 | 선택 | 비고 |
|---|---|---|---|
| 저장소 SQL 전부 + 외부 자재·법령 칸 | 33 있음 · 1 없음 | 4 있음 · 2 없음 | 없음: `categories.discount_corporate`(저장소에 만드는 SQL 없음) |
| 운영 추정(외부 자재·법령 칸 없음) | 33 있음 · 1 없음 | 6 없음 | 위와 같음 + 외부 자재·법령 칸 없음(정상) |
| 기존 로컬 테스트 DB(tomokmall_test) | 24 있음 · 10 없음 | — | 테스트 DB 구축 스크립트가 일부 SQL 을 적용하지 않음(4장) |

- `categories.discount_corporate`(기업 마진율): `app/pricing.php` 가 쓰지만 저장소의 어떤 SQL 도 만들지 않는다. 없으면 오류 대신 **기업 마진 0%(매입가)** 로 계산된다(기존 동작, 이번 변경 아님). 운영에 있어야 정상 — 위 SQL 로 확인.

2. 비교(로컬 전용 신규 도구):

## 6. 백업·롤백

### 6-1. 백업(업로드 직전)
- 파일: 5-1 의 FileZilla 다운로드(서버 `/app` 전체 + `/html` 대상 파일, 가능하면 `/html` 전체에서 업로드 이미지 폴더만 제외). `backup/<날짜>-filezilla/` 에 보관하고 지우지 않는다.
- DB: 이번 배포는 구조·데이터를 바꾸지 않지만, 상담 로그 등이 계속 쌓이므로 phpMyAdmin **내보내기(전체)** 를 권장(되돌릴 때 기준점).
- 기록: 배포 커밋 `02a98c2`, 비교 결과, 업로드 시각.

### 6-2. 롤백(문제 발생 시 — 재업로드도 승인 필요)
1. 백업 폴더의 파일을 FileZilla 로 **역순**(12 → 2번)으로 다시 올린다. 1번 `external_products.php` 는 이전 코드가 쓰지 않아 남겨도 무해(지우려면 별도 승인).
2. `bash scripts/compare-server-files.sh <롤백 후 다시 내려받은 폴더> 516950f …` → 모두 `같음` 이면 복구 완료.
3. 브라우저로 메인·검색·AI 상담·견적 확인.
- 예상 소요: 파일 12개 재업로드 수 분. DB 를 바꾸지 않으므로 DB 롤백은 없다.
- 대안: `scripts/deploy-files.sh`(curl, 백업·비교·업로드 검증·복구 자동)는 **기존 파일 11개에만** 쓸 수 있다(서버에 없는 신규 파일은 check 단계에서 멈춤) → 신규 1개는 FileZilla 로.

`bash scripts/smoke.sh`(운영 대상 — 배포 승인과 함께 실행 승인), 브라우저: 메인·카테고리·검색·상품 상세·로그인·마이페이지·AI 상담(비교 질문 1회 + 견적추가)·견적·기업 메인·직원·관리자.
