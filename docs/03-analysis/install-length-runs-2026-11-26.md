# AI 상담 설치 길이 질문·줄별 수량·질문 방식 (2026-11-26, 사용자 결정 B안)

## 1. 문제 (지금 구조 분석)
- 질문이 "설치 길이(m)" 하나뿐이고 도구도 설치 길이를 숫자 하나(`length_m`, 총 길이)로만 받았다. 고객이 "10m"라고 답하면 한 줄인지 합계인지 알 수 없었다.
- 빠른 상담 `quick_install_amount()` 가 "10m씩 2줄"·"10m 2줄"·"양쪽 20m씩"을 **10m·20m 한 줄로 읽어 수량이 절반**이었고, "10m, 15m"는 읽지 못했다.
- 경계석은 보도블록과 같은 필수 항목 묶음이라 **면적(㎡)을 물었고**, 흄관은 상담 품목 감지(`rag_detect_category`)에서 관류로 잡히지 않아 **설치 길이를 묻지 않았다**('기타 자재').
- 수량은 "합계 ÷ 1개 길이"를 한 번만 올림 — 여러 줄이면 줄 끝 자투리 때문에 실제보다 적게 나왔다(2m 수로관 7m×3줄: 11본 → 실제 12본).

## 2. 결정 (2026-11-26 마스터님 — B안)
문구 + 서버가 줄 구성 읽기 + 줄마다 수량 계산. 두 상담(기존 AI 상담 `/chat.php`·우측 하단 빠른 상담) 모두, 화면·대화 흐름은 그대로, 가격 데이터·단가·마진율·가격 계산식은 그대로.

## 4. 수량 규칙 (자재별 시공 특성)
| 자재 | 계산 | 이유 |

### 4-1. 절단 잔여분 재사용 근거 확인 (2026-11-26 마스터님 요청)
- 처음 구현은 PE·PVC 관류(이중벽관·유공관·PVC관 등)를 '잘라서 이음관으로 잇는 자재'라 보고 합계로 계산했다(가안). 이 판단은 자를 수 있다는 일반 지식뿐이었고, 출처가 없었다.
- 제조사 공식 시공지침·국가건설기준(KDS·KCS 하수관로 등)에서 '절단 잔여분을 다른 설치 구간에 이어 써도 된다'는 근거를 찾지 못했다(웹 검색 — 국내 하수관로 논문·시공 자료, 해외 HDPE 관 설치 지침 목록 수준. 원문 전체 검토는 하지 않음).
- 사용자 결정(11-26): 근거가 없으면 재사용을 가정하지 않는다 → **개·본 단위 길이 자재는 PE·PVC 관류 포함 모두 줄마다 올림**, 미터 단위 판매는 합계, 재사용이 검증된 자재만 예외(`INSTALL_RUNS_REUSE_VERIFIED` — 지금 비어 있음, 근거 문서와 함께 더함).

- 예상 자재비 = 단가 × 수량(기존 식). 견적 목록·견적 카드 금액 = 표시 단가 × 바뀐 수량(`quote_draft_build` 그대로) — `tests/install_runs.test.php` 에서 로컬 테스트 DB 로 확인.
- 한 줄이면 계산·근거 문구가 반영 전과 같다(`21m ÷ 2m = 11본`).

## 5. 질문 방식 (공통 대화 지침 — 특정 자재가 아니라 모든 질문)
1. 안내형 질문("~을 알려 주세요"), "~알고 계신가요?"·"~알 수 있을까요?" 같은 돌려 묻기 금지
2. 무엇을 답하면 되는지 분명히 — 헷갈리는 값(치수·길이·면적·관경·수량)은 단위와 짧은 예시를 질문에 함께
3. 필요한 정보는 한 메시지에 한 번에(2~3개), 추천에 필요 없는 것은 묻지 않음
4. 이미 말한 정보(같은 현장 다른 자재 포함)는 다시 묻지 않음
5. 정확한 규격을 모르면 대략값·현장 설명·가장 많이 쓰는 규격으로 먼저 보여 주기로 이어 감
6. 친절·전문적, 공문체·같은 인사 반복 금지
- 설치 길이 질문 문장(길이 자재 공통): "설치 길이(m)를 알려 주세요. 여러 줄을 설치하는 경우 각 줄의 길이를 알려 주세요. (예: 10m씩 2줄 또는 10m, 15m)" — 길이·개수를 모를 때만.
- 품목별 [필수 확인 항목]은 "무엇을" 물을지만, "어떻게" 묻는지는 이 구역 한 곳에서 관리(`RAG_QUESTION_STYLE_PROMPT`).

## 8. 맞는 규격이 없을 때 유사 제품 표 (2026-11-26 마스터님 요청)
- 답 첫 문장 고정: **'해당 규격의 제품이 없습니다. 대신 아래에 유사한 제품을 추천해드립니다.'** 다음 줄에 무엇이 다른지 한 줄, 그 아래 유사 제품 표(수량·금액은 기존 계산 그대로).
- 폭·길이가 다름 → 같은 하중 조건에서 가장 가까운 등록 치수(차이가 같으면 큰 쪽) 제품. 반드시 지킬 규격(spec_strict)이 없음 → 같은 품목의 다른 규격(요청 값과 가까운 순). 필요한 하중 등급이 없음 → 한 단계 높은 등급('필요보다 튼튼하고 가격이 높을 수 있음').
- **안전 규칙은 그대로**: 낮은 하중 등급·차량용 포장 블록 두께(80T·공공 차도 100T)보다 얇은 블록은 유사 제품으로도 보이지 않는다(기존 '적합 상품 없음' 안내 유지).
- 빠른 상담은 유사 제품을 자동으로 담지 않는다(고객이 고름).
- 스위치 끔 = 반영 전(표 없이 안내만). 검증: `tests/quick_similar.test.php` 26, `ai_search` 유사 제품 3건 추가(끈 상태의 옛 기대값도 유지).

## 9. 운영 시험 후속 (2026-11-27 마스터님 요청)

운영 시험(11-27, Windows Chrome)에서 본 세 가지를 고쳤다. 스위치는 `FEATURE_AI_INSTALL_RUNS`(1·2)·`FEATURE_AI_SIMILAR_PRODUCTS`(3, 같은 용도 넓히기).

1. **경계석은 장소부터**: 경계석만 말하고 설치하려는 말(길이·필요·추천·설치·견적)이 있는데 설치 장소·차량을 모르면, 검색하기 전에 서버가 고정 질문을 한다(`rag_curb_place_question` — 빠른 상담 첫 질문과 같은 문장, 두 상담 공통). 장소를 말했거나 다른 자재와 함께 물으면 그대로 GPT 가 답한다.
   **근거 없는 문장 빼기**(`rag_strip_unsupported_claims`): '신뢰성이 높습니다'·'내구성이 뛰어납니다'·'튼튼'·'균열 방지' 같은 효과 문장과, 하중이 상품 자료(load_check)로 확인되지 않은 표에서 '하중을 견딜 수 있는'·'차도에 적합한' 같은 문장을 뺀다. 'KS … 대상 종류이므로 신뢰성이 높습니다'는 '…종류입니다.'로 사실만 남긴다. 두께 기준(80T 등 숫자) 문장은 그대로.
2. **줄별 수량 기준**: 여러 줄이면 답에 '수량 기준(줄별 10m·15m): 10m 4본 + 15m 6본 = 10본(줄마다 ÷ 2.5m 올림)' 한 줄을 서버가 넣는다(GPT 가 이미 말했으면 넣지 않음, 제품 1개 길이가 다르면 제품별). 계산 근거(qty_basis)도 줄 길이를 함께 적는다('4본 + 6본' → '10m 4본 + 15m 6본').
3. **같은 종류·같은 용도 유사 제품**: 운영 기록 #378 — 빠른 상담이 '폭 320 10m씩 2줄 승용차'에 **검색하지 않고** '그레이팅 수로용은 등록되지 않음'이라고 답했다(운영에는 그레이팅수로용 77개 판매 중). ① 품목을 앞선 말에만 말했어도 치수를 말하면 검색을 강제하고, 검색 없이 '등록되지 않음·취급하지 않음'이라고 단정한 답도 버리고 검색한다. ② 검색어 이름의 상품이 아예 없으면 **용도가 분명할 때만** 같은 종류에서 찾는다: 그레이팅 + 수로(배수로·측구·트렌치) → '그레이팅 수로용', 그레이팅 + 맨홀·집수정 → '그레이팅 맨홀'(맨홀·집수정 본체는 빼고 그레이팅만). 유사 제품 표 첫 문장 + '요청하신 ○○ 제품이 없어 같은 용도의 다른 그레이팅 제품입니다'. 용도를 모르면 넓히지 않는다. ③ 맨홀·집수정용 그레이팅을 찾으면 수로용 그레이팅이 섞이지 않게 했다(전에는 수로 검색만 맨홀용을 뺐음).

### 9-1. 배포(#2543) 후 운영 시험에서 고친 것 (2026-11-27)

- **빠른 상담 '폭 320 10m씩 2줄 승용차' → 여전히 '등록되지 않았습니다'**: 기록 #383 에 표·제품 카드가 없었다. 같은 조건을 로컬에서 시험해 보니 GPT 가 '10m씩'의 10m 를 **제품 1개 길이**(product_length_mm 10000)로 넘기면 '폭 320mm·길이 10m 제품 없음'(0개)이 되어 같은 답이 나온다. 이제 GPT 가 넘긴 제품 길이가 고객이 말한 줄 길이·합계와 같으면 제품 길이 조건을 빼고 설치 길이로 옮긴다(`rag_apply_runs`) → 가장 가까운 폭 300mm 유사 제품 표.
- **경계석 답의 '두께가 120mm로 … 저희 권장 기준을 충족합니다'**: 포장 블록 두께 기준을 경계석에 댄 문장. 경계석만 이야기하는 상담(`rag_is_curb_only`)에서는 '권장 기준'·'80T 이상/기준'·'두께 … 기준/충족' 문장을 숫자가 있어도 뺀다(`RAG_CURB_THICK_CLAIM_RE`). 보도블록 등 다른 상담의 두께 기준 문장은 그대로.
- **표에 없는 치수 덧붙이기**(마스터님 요청 11-27, 기록 #380 — 120×120×120 경계석에 '길이 1m'): 답 글 줄마다 이름이 나온 이번 표 제품의 규격·세부 치수·수량 근거 숫자와 고객이 말한 숫자에 없는 치수 말('길이 1m'·'두께 80mm' 등)을 서버가 뺀다(`rag_strip_unlisted_dims`). 'A, 길이 1m, B' → 'A, B', 혼자인 문장은 빼되 줄 앞 '- 제품명:'은 남긴다. 설치 길이·이름 없는 줄(앞 대화 제품·일반 안내)은 건드리지 않는다. mm·m 는 같은 값으로 본다(1000 = 1m).
- **경계석 카드 '고르는 기준'**: '인조화강경계석'이 이름 때문에 인조화강 포장 블록으로 읽혀 카드 기준에 '두께 120mm — 차량이 올라가는 곳 저희 권장 기준(80mm 이상) 충족'이 붙었고, GPT 가 이 문장을 답에 옮겼다. 경계석·연석 이름이면 블록 두께 기준을 붙이지 않는다(`ext_selection_guide`, '콘크리트 블록' → '콘크리트 제품').
- '10m씩 2줄'은 길이 10m 제품이 아니라 **설치 길이**: 1m 그레이팅이면 '10m×2줄: 한 줄 10m ÷ 1m = 10개 × 2줄 = 20개'.
- **배포(#2588) 뒤에도 빠른 상담 그레이팅 '등록 안 됨' — 진짜 원인**(운영 DB 조회로 확인): 폭 320mm 그레이팅은 없어 검색이 넓어지면서(OR) 규격에 320 이 들어간 수로관 본체·집수정 6개(원형사각수로관 RDG형 D200·NS용집수정 — 설명에 '그레이팅' 글자)만 걸렸고, 덮개만 남기는 단계에서 0개가 되어 "'그레이팅 수로용'(덮개) 단품은 사이트에 아직 등록되지 않았습니다"(덮개 미등록 안내)로 끝났다. 로컬 복제 DB(11-23)에는 이 상품들이 없어 재현되지 않았다. 이제 같은 이름의 덮개가 판매 중이면(치수 조건 없이 찾으면 덮개가 있음) 덮개 미등록이라 하지 않고 가까운 치수 유사 제품(폭 300mm)으로 간다. 함께: 등록 치수·가까운 치수 후보를 80개 → 600개(`AI_DIM_POOL`), 차량 조건이 있으면 검색 후보 300개 — 운영 그레이팅 수로용이 241개로 늘어 가벼운 등급 이름이 위를 채우는 경우 대비.
- **덮개가 정말 없을 때 안내 문장**(마스터님 요청 11-27): 검색에 걸린 수로관 본체·집수정(원형사각수로관·NS용집수정 등)은 덮개가 아니므로 이름을 말하지 않고 "해당 조건에 맞는 '○○' 상품은 사이트에 등록되지 않았습니다. 다른 조건(폭·용도 등)으로 찾아보시거나 견적요청하기로 문의해 주세요."로만 끝낸다(`ai_cover_missing_note` — 예전 '그레이팅 규격이 옵션으로 표기된 제품'·'덮개가 아니라 수로관 본체' 안내는 뺌). 같은 이름 덮개가 판매 중이고 치수만 다르면 이 문장이 아니라 가까운 치수 유사 제품 표(A15).
