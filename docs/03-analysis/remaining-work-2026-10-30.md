## A. 남은 오류

### A-1. 닷홈이 API 오류 응답 본문을 바꿔 오류 문구가 사라짐 — 우선
- 원인: 닷홈 Apache 가 400·401·405 등 **4xx 응답 본문을 기본 HTML 오류 페이지로 바꾼다**(2026-10-30 운영 확인: 400·401·405 모두). API 가 보낸 JSON 오류 문구가 화면에 오지 않고, 화면의 `r.json()` 이 실패한다.
- 이미 대응된 곳: `public/quote.php`(견적 접수) — 실패도 200 + `ok:false` 로 돌려 문구가 나온다(코드 주석에 같은 원인).
- 영향(코드 확인 — 운영에서 직접 재현은 장바구니만):

| 화면 | API | 운영에서 보이는 것 | 원래 의도한 문구 |
|---|---|---|---|
| 로그인 | `api/auth/login.php`(401) | **'네트워크 오류가 발생했습니다.'** | 아이디·비밀번호 오류 등 |
| 회원가입 | `api/auth/register.php`(4xx 11곳) | 일반 오류 문구 | 중복 이메일·입력 형식 등 |
| AI 상담 비교표 '견적추가' 1,000개 | `api/cart.php`(400) | '상품 가격·판매 상태를 확인하지 못해 담지 못했습니다' | '수량은 1~999 범위여야 합니다' |
| 견적 화면 수량 변경 | `api/cart.php` | '변경한 내용을 저장하지 못했습니다' | 같음 |
| 기업 즉시견적·즐겨찾기·재주문·마이페이지·현장·주문·직원·관리자 | 4xx 사용 API 총 23개 | 각 화면의 일반 오류 문구 | 각 API 문구 |

- 해결안: `quote.php` 방식 — 검증 실패는 **HTTP 200 + `{"ok":false,"error":…}`**, 인증 실패만 프런트가 상태 코드로 처리. 1차 범위: 로그인·회원가입·견적 담기(`api/cart.php`) → 이후 나머지 API.
- 확인: 로컬 단위·통합 테스트 + 운영 배포 후 잘못된 비밀번호 로그인 1회(사용자) — DB 변경 없음.

### A-2. 견적 상태 정책 불일치 → 배송 내역 항상 빈 목록 (정책 결정 필요)
- 운영 `estimates.status` = `REQUESTED·SENT·APPROVED·EXPIRED·CANCELED`(기본 REQUESTED). 코드 일부(`alter_estimates_v2.sql` 의도, 배송 내역 API)는 `PENDING·CONFIRMED·DELIVERED` 를 쓴다.
- 영향: 마이페이지 배송 내역은 `DELIVERED` 를 찾아 **항상 빈 목록**(오류는 아님). 직원·관리자 화면은 REQUESTED 계열을 쓰므로 현재 견적 처리는 동작.
- 결정 필요: 납품 완료를 어떤 상태로 표시할지(ENUM 에 `DELIVERED` 추가 vs 배송 내역 조건 변경 vs 보류).
