## 1. GPT 호출·도구 전달 구조 (분석)

```
chat.php → rag_process(messages, sid)
  ├ rag_recent_cards(sid) · rag_recent_cond(sid) · rag_session_shown_ids(sid)   ← chat_logs.events_json(product_cards + cond)
  ├ rag_build_prompt() — 시스템 프롬프트 + '직전 추천표'(마지막 표의 id·단가·수량만)
  └ OpenAI 반복(최대 3) — GPT 가 search_products 인자를 만든다
       raw_input(GPT 값) → rag_prepare_search_input(서버 보완, fills 기록) → tool_search_products → 결과(note·recheck·카드) → GPT
```

대화 기록에는 글만 남고 도구 결과는 남지 않는다. 그래서 GPT 는 **마지막 표의 id 만** 알고, 바꾸지 않은 조건도 매 턴 스스로 다시 넘겨야 한다. 여기서 생기는 실수:

| 약점 | 예 | 서버 보완(고객 말에 분명히 있는 것만) |
|---|---|---|
| 조건 누락 | '폭은 400으로 바꾸고 길이는 그대로' → 제품 길이 빠짐 | 같은 품목이면 앞서 말한 폭·제품 길이·설치 길이 유지 |
| 옛 값 재사용 | 폭 400 으로 바꿨는데 width_mm 500 | 마지막 고객 말의 값으로 |
| 칸 혼동 | '길이 1m 그레이팅' → length_m 1(설치 길이) / '설치 20m' → product_length_mm 20000 / 폭 → spec_mm | 고객 말로 칸을 옮김 |
| 제외 범위 | '앞에 보여준 제품은 빼고' → 마지막 표 id 만 | 이 상담에서 보인 제품 전체를 더함 |
| 금액 기준 | 조건이 바뀐 뒤 옛 표 금액으로 '더 저렴한' | 같은 조건일 때만 기준, 아니면 이유와 함께 비교 안 함 |
| 통행 | GPT 가 traffic 을 빠뜨리거나 반대로 | 분명한 말(차량이 다녀요·사람만)은 고객 값, 장소 짐작은 빠졌을 때만 |

서버가 읽는 말(`rag_explicit_conditions`): 폭 = '폭/너비 N'·'N 폭'·'W500', 제품 1개 길이 = '제품/1개 길이 N'·'길이 N(인·짜리) 품목이름'·'L1000', 설치 총 길이 = '설치/시공 구간 N m'·'총 N m'·'연장 N m'·'N m 구간'·'N m 설치'.
'길이는 10m야'처럼 어느 길이인지 말에 없거나 '길이 10m 그레이팅'(6m 초과)은 서버가 정하지 않는다(GPT 판단). 높이·직경·관경·두께는 폭·길이로 만들지 않는다.
