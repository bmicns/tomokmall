# PHP 코드 원칙·백엔드 보안 (P1·P2)

> 가격 계산(`app/pricing.php`)·가격 저장 경로는 `CLAUDE.md` P0-4 가 우선한다.

## 1. 공통
- 기존 파일의 스타일·네이밍·주석 밀도를 따른다(snake_case 함수, `declare(strict_types=1)`, 파일 상단 책임/금지 주석).
- 한 함수는 한 가지 일. 새로 만들기 전에 `app/` 에 있는 헬퍼를 찾아 재사용한다.
- 매직 넘버·하드코딩된 URL/가격/비율은 설정이나 상수로 둔다. 단, 기존 구조를 크게 바꾸면서까지 하지 않는다.
- 새 라이브러리·프레임워크·빌드 도구 도입은 C등급(사용자 승인 후).
- 죽은 코드로 보여도 바로 지우지 않는다. 사용처가 없다는 근거와 함께 삭제를 **제안**한다.

## 2. 백엔드
- DB 접근은 `db()`(PDO) + **Prepared Statement** 만. 사용자 입력을 SQL 문자열에 직접 붙이지 않는다.
- 모든 입력은 서버에서 검증(타입·범위·길이·필수값). 클라이언트 검증만 믿지 않는다.
- 출력은 `htmlspecialchars($v, ENT_QUOTES)`(XSS 방지). JSON 은 `json_encode(..., JSON_UNESCAPED_UNICODE)`.
- API 는 권한 함수(`require_login`/`require_corporate`/`require_admin` 등)로 보호하고, 다른 사용자의 데이터(주문·견적·현장)에 접근하지 못하게 **소유자 확인**을 한다.
- 상태를 바꾸는 요청은 POST(또는 적절한 메서드)만. GET 으로 데이터 변경 금지.
- `display_errors` 는 운영에서 끈 상태 유지(`bootstrap.php`). 사용자에게는 일반 메시지, 상세는 서버 로그.
- 가격·마진·할인 계산과 수량 계산은 영향이 크므로 수정 시 단위 테스트를 추가한다(가격 계산 변경 자체는 P0-4-4).
- 외부 API(OpenAI 등) 호출은 타임아웃·실패 처리를 두고, 장애 때도 상품 조회·견적·주문이 동작하게 격리한다. 키는 `getenv()` 로만 읽는다.

## 3. 보안·성능 점검
- **보안**: SQL 인젝션, XSS, 권한 우회(IDOR), CSRF(현재 SameSite=Lax 쿠키에 의존 — 민감한 기능 추가 시 토큰 도입 검토), 파일 업로드 확장자·크기 검증, `public/.htaccess` 의 `.env`·`.git` 접근 차단 유지, 웹루트에 관리용·디버그 스크립트 두지 않기.
- **성능**: 반복문 안의 쿼리(N+1) 피하기, 필요한 컬럼만 SELECT, 검색 조건 컬럼 인덱스 확인, 큰 이미지 최적화, 불필요한 외부 API 호출 줄이기.
