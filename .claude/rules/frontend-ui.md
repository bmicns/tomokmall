# 화면·접근성·반응형 (P2)

> 주요 UI/UX 변경은 C등급(`workflow.md` 2장). 보고 때 데스크톱·태블릿·모바일 확인 결과(또는 확인 못 한 항목)를 구분해 적는다.

## 1. 프론트엔드
- UI 는 `docs/style-guide.md` 와 기존 레이아웃(`layout.php`, `admin_layout.php`, `staff_layout.php`)을 따른다.
- JS 는 `public/assets/` 의 기존 방식(바닐라 JS, `fetch`)을 유지한다. `innerHTML` 에 서버/사용자 데이터를 넣을 때는 이스케이프한다.
- 시맨틱 HTML, `lang="ko"`, `viewport` 메타를 유지한다.
- 이미지·정적 파일 이름을 바꾸면 참조하는 모든 곳을 함께 확인한다(한글 파일명 포함).

## 2. 접근성
- 이미지 `alt`, 폼 `label`, 키보드 조작 가능, 충분한 색 대비, 버튼은 `<button>`.

## 3. 반응형
- 새 기능·기존 UI 수정 때 데스크톱뿐 아니라 **모바일(360px)·태블릿**도 함께 고려한다. 겹침·잘림·가로 스크롤이 생기지 않게 한다.
- **기존 반응형 레이아웃과 방식을 우선**한다. 새 브레이크포인트·CSS 프레임워크를 만들기 전에 `public/assets/styles.css` 와 해당 페이지의 기존 `@media` 규칙(현재 1200/900/800/640/600/520px 등)을 확인해 재사용한다.
- 체크박스·버튼·입력창은 터치 환경에서도 편하게: 라벨 전체 클릭 가능, 충분한 터치 영역(약 44px 내외)·간격, hover 에만 의존하는 동작 금지.
